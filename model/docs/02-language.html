第 2 章

统一语言

统一语言（Ubiquitous Language）是领域建模里最便宜、收益最高的一件事： 把词定死。产品说"这一步失败重来"，开发说"retry"，测试说"重新跑"—— 如果三者指的不是同一件事，后面所有讨论都会慢慢跑偏。

这一页就是这本"词典"。建议先扫一遍，后面看四章时随时回来查。

2.1为什么词要定死

拿三个最容易混的词举例：

说法到底指什么谁在管
"这个任务失败了"是一个步骤失败？一次尝试失败？还是整个计划失败？三种，全不同
"让它重来一次"重试同一个步骤？改计划？还是重新思考为什么错？重试 / 重划 / 反思
"保存一下上下文"往流水里追加一条记录？还是压缩成摘要？追加 / 折叠

定死之后，讨论就变成"这一步的第三次尝试验证失败了，外循环要决定重试还是重划"——不会再有歧义。

2.2核心术语表

A. 会话与上下文（感知模块）

术语英文 / 代码名通俗解释
会话Session一次对话的"现场"。它保存了你和模型说过的每一句话、工具返回的每个结果，以及一开始拍下的提示词快照。
子会话Session.parentSessionId主会话派出去干活的"分身"。它是一次完整会话（有自己的上下文和计划），只是由主会话发起。
会话族root Session主会话 + 它派出的所有子会话，算一家人。token 花销按"一家人"合计。
记录Record上下文流水里的一条：谁说的、说了什么、什么时候说的。只追加，不修改。
记录角色RecordRole这条记录是谁写的：系统 / 用户 / 模型 / 工具请求 / 工具结果 / 摘要。
上下文窗口ContextWindow这次真正发给模型的那一批记录。不是全部历史，是"当前能装进去的那一段 + 摘要"。
上下文用量ContextUsage窗口里用了多少 token、上限多少、其中系统提示占了多少。
折叠（压缩）summarization历史太长时，把旧记录压成一条"摘要记录"，给新内容腾地方。用户会看到"压缩中"。
系统提示词快照SystemPromptSnapshot会话开始时把"人设 + 工具说明 + 技能清单"拍一份内容照，之后运行中不再受定义变更影响。
会话续跑resume关掉终端后再打开，把历史会话接着跑。半截的工具调用按失败处理。

B. 执行与验收（规划模块）

术语英文 / 代码名通俗解释
计划Plan模型把任务拆成的一串步骤。严格按顺序做，不并行。
步骤PlanStep计划里的一步。它自己声明"这一步该怎么验证"。
尝试Attempt一个步骤的一次完整执行周期。可能中间被你插话几次，但仍然是同一次尝试。
轨迹区间RecordRange这次尝试对应流水里的哪一段。用"起点记录 ID + 终点记录 ID"表示，不重复存内容。
提交submit_step模型声明"这一步我做完了"，并附上产出摘要。模型不提交，这一步就一直没完成。
收敛converged模型不再调用工具，这一轮说完了。注意：收敛不等于完成。
验证链VerificationType × 链验收这一步的流水线，最多四道：确定性规则 → 外部反馈 → 模型裁判 → 人工审批。
验证报告VerificationReport验收结论：通过 / 不通过 / 无法判定，以及失败发生在哪道、原因是什么。
重试retry同一步骤再做一次（换做法），会消耗一次重试名额。
反思Reflection失败到一定次数后，让一个"军师"代理分析为什么失败，结论会喂给下一次尝试。
重划replan重做计划：只替换还没执行的那部分，已完成的步骤保留。
固化succeeded 不可变步骤成功后，它的产出与记录就锁死，不再改动。
中断INTERRUPTED你按了 Ctrl-C 或关掉程序。这次尝试作废，但不算一次失败。

C. 能力与执行器（行动模块）

术语英文 / 代码名通俗解释
工具ToolDefinition模型能调用的一个动作。有入参 schema、出参说明、超时、副作用等级。
内置工具SourceType.INTERNAL应用自己实现的那几个：生成计划、提交步骤、问用户、开子代理、加载技能。
副作用等级SideEffectLevel只读 / 可重复 / 不可逆。决定执行前要不要先问你要不要放行。
信任清单trustedToolIds你自己维护的一份"这些工具不用问我"的白名单。连不可逆工具也能放进去。
代理AgentDefinition一个"角色"：人设 prompt + 能用哪些工具 + 能用哪些技能。
内置代理AgentSource.BUILT_IN系统自带的四个角色：反思、裁判、检索经验、归纳经验。人设不可改、工具写死。
技能SkillDefinition一份"怎么做好某类事"的操作手册（SOP）。它不携带工具，只教方法。
SOPInstructionTemplate技能的正文。默认只给模型看标题和简介，它需要时才加载全文。
供应商Provider模型的服务商（端点 + 凭据）。一个供应商下可以有多个模型。
模型Model具体可调用的模型：上下文上限、能力标签（如视觉、函数调用）、状态。
预算Budget会话族的 token 台账。只记账、只预警，不硬中断。

D. 学习（记忆模块）

术语英文 / 代码名通俗解释
反思Reflection失败后的复盘结论。它有两个用处：喂给下一次尝试、作为经验素材。
沉淀（蒸馏）distillation计划结束时，把这次的反思蒸馏成一条"经验"。只有能让任务最终成功的反思才算好素材。
经验Experience一条可复用的教训：什么场景下、该怎么做。不绑定任何代理或工具，全局共享。
置信度ConfidenceScore这条经验有多可信（0~1）。被用对了加分，用错了减分，低到一定程度就淘汰。
检索ExperienceRetriever新计划生成时，让一个子代理从经验库里挑出"对这几步有用的"。

E. 运行环境（策略）

术语英文 / 代码名通俗解释
运行策略RuntimePolicy所有"用户可以调"的全局参数：重试几次、什么时候反思、窗口多长、经验库多大……
安全余量inputSafetyMargin算上下文上限时预留的 token（默认 10000），防止估算偏差。不是给输出预留的。
最大 ReAct 轮次maxReActRounds唯一一道硬闸：一次尝试里最多让模型连多少轮工具。超了就判失败。

F. 建模词汇（读图用）

术语含义怎么认
聚合 / 聚合根一组必须"同时改对"的对象，外面只能通过根去改它图上标 <<AggregateRoot>>
实体有身份标识、会变的对象（改属性还是同一个它）标 <<Entity>>
值对象没有身份，只看内容；内容一样就是相等，且不可变标 <<ValueObject>>
领域服务一个"动作"，它跨多个对象协作，不属于任何一个对象标 <<DomainService>>
领域事件"某事发生了"的通知，由聚合根在状态变化后发出标 <<Event>>，箭头写 raises
应用事件过程性通知，不对应任何聚合状态变化（如"开始压缩了"）单独一个命名空间
端口一个"插座"：A 模块只声明接口，B 模块提供实现，避免互相依赖标 <<Port>>
不变量永远必须成立的规则；一旦会破坏它，这个操作就不该被允许每章"聚合清单"的最后一列
ID 引用跨聚合只存对方的 ID，不存对象本身图上的虚线箭头

2.3最容易混淆的七组概念

① 会话 / 计划 / 尝试 —— 三个"容器"

会话计划尝试
装什么所有说过的话一串要做的步骤某一步的一次执行
一个会话里有几个—0 到多个（闲聊就是 0）每步可以有多个（重试就有多个）
什么时候结束归档或删除成功 / 失败提交 / 失败 / 中断

② 收敛 / 提交 / 验证通过 —— "做完了"的三个层次

  • 收敛：模型这一轮不调工具了。只说明它话说完了。
  • 提交：模型主动说"这一步我做完了"（submit_step）。这是它的自我声明。
  • 验证通过：验收流水线判定产出合格。这才是真正的"做完"。

三者缺一不可：只收敛不算完；只提交不过验证也不算完；没声明验证的步骤则是"提交即完成"（这是模型的合法选择，但有风险）。

③ 验证 / 反思 —— 一个判对错，一个想办法

验证反思
回答的问题"这算不算做对了？""为什么老是做不对？"
产出验证报告（三态结论）反思结论（一段可执行的建议）
什么时候发生每次提交后（如果声明了验证）失败达到阈值后
给谁用外循环决定推进/重试喂给下一次尝试 + 沉淀成经验

④ 经验 / 技能 —— 陈述性知识 vs 程序性知识

  • 经验："上次这么干翻车了，别这么干。"——是踩过的坑，模型自动获得（检索后注入）。
  • 技能："做这类事的标准流程是 1、2、3。"——是操作手册，模型主动加载（load_skill）。

⑤ 工具失败 / 模型不可用 / 请求超限 —— 三种"不顺利"

情形性质怎么处理
工具报错、超时正常业务的一部分当成一种"工具结果"喂回模型，它自己想办法
模型连不上（备用链全挂）环境故障暂停，什么都不改、不消耗重试、不自动重试
请求超过模型上下文上限预算问题强制压缩一次再试；还不行就按环境故障处理

⑥ 重试 / 反思 / 重划 —— 三条不同的"再来一次"

重试反思重划
改什么同一步换个做法不改动作，只改"下次怎么想"改计划本身
消耗重试名额是否（反思是一次额外调用）否（消耗重划代次）
谁触发验证不通过失败次数达阈值重试用尽 / 用户要求

⑦ 归档 / 删除 / 续跑 —— 会话的三种"离开"

  • 关终端：不是状态变化，只是程序没了；下次可以续跑。
  • 归档：保留数据，但不能再续跑。
  • 删除：物理删除这个会话族的记录、计划、预算；已沉淀的经验保留（经验是全局资产）。

枚举取值用在哪

2.5命名约定

东西约定例子
状态动词统一用 submit / activate / deprecate不再混用 publish / deactivate
事件命名过去式，"某件事已经发生了"PlanCompleted、ExperienceCreated
跨聚合引用只存 ID，命名 xxxIdsessionId、verificationReportId
值对象名词短语，不可变ContextUsage、RecordRange
时间戳一律 xxxAt / xxxDatecreatedAt、decidedAt
