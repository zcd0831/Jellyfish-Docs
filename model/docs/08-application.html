第 8 章

应用层

应用层回答一个问题：一次用例，按什么顺序、在什么事务里、通过哪些端口，把领域对象推动起来。 它不含业务规则（规则在领域层），也不含技术细节（文件、网络、终端都在基础设施层）。

一句话：领域层只决定，应用层只执行。

用例 6 应用组件 12 端口 21 不含业务规则

8.1定位与边界

方向内容
本层对象6 个用例服务 + 12 个应用内组件
本层依赖领域层（聚合方法、领域服务、领域策略）——只读调用，不实现规则；21 个端口（只认接口）
谁依赖本层外壳（TUI / CLI / Server）只调用例服务
本层不负责状态机与不变量（领域层）、文件与网络与终端（基础设施层）
三条纪律
  1. 用例服务里不写业务判断——"算不算完成""该不该淘汰""哪些层要验证"，都问领域对象；
  2. 绝不跨 IO 持事务——模型调用、工具执行、ask 阻塞、子代理 join 全在提交之外；
  3. 本层不出现 File、Path、HttpClient、System.out——一切经端口。

8.5用例清单

用例触发输入输出事务数主要失败分支
StartSessionUseCase 用户开新对话 / 主会话派出子代理 agentId?、modelId?、首条输入 sessionId 1 Agent/模型不存在；标题生成失败（降级首句截断，不失败）
RunSessionUseCase 用户发一条消息 sessionId、文本、CancellationToken 本轮是否收敛 + 会话状态 0..N 模型不可用（返回、不改状态）；请求超限（折叠一次后重试）；用户中断（INTERRUPTED）
ResumeSessionUseCase 程序重启后用户选择续跑 sessionId 续跑结果 1 + N 会话已归档；计划不可恢复
ManageSessionUseCase 用户取消 / 归档 / 删除 sessionId、动作 无 1 会话不存在（幂等）
AdjustPolicyUseCase 用户改设置 新参数 无 1 校验失败（拒绝，不改）
ManageCatalogUseCase 增删改工具 / 代理 / 供应商 / 模型 / 技能 目标实体 + 变更 无 1 内置代理不可改；id 冲突（builtin. 前缀保留）
没有 AnswerUserUseCase

人机交互是阻塞端口（HumanInteractionPort.ask），答案在调用栈里直接返回，不构成一个用例。

8.8事务与提交顺序

8.8.1 文件系统没有跨文件原子性，所以用「顺序 + 幂等 + 对账」代替

CommitScope 的契约：应用层只管 stage 要写什么，执行顺序由基础设施强制：

① 不可变事实（reports / reflections / experience 新文件）
② 追加流水（records-NNNN.jsonl 追加一行）
③ 替换聚合（meta.json / plans/*.json / budget.json / settings.json）

这样任何崩溃点都只落在「事实已存在、状态未推进」，永远不会出现「状态推进了、事实不存在」。恢复方向因此是单向补齐。

8.8.2 一次 RunSession 里的事务清单

#事务写入事务外先完成的 IO
T1追加用户输入RecordStore +1 条—
T2上下文折叠追加 SUMMARY调模型生成摘要
T3记录工具请求追加 TOOL_REQUEST—
T4记录工具结果追加 TOOL_RESULT工具执行（含超时）
T5token 记账budget.json 累加—
T6步骤结案VerificationReport + plan.json跑验证链（模型 / 人工）
T7尝试判败 / 中断plan.json—
T8经验分配plan.json（assignedExperienceIds）检索子代理
T9计划重划plan.json（代次+1、SUPERSEDED）调模型生成新计划
T10经验反馈experience/*.json—
T11经验沉淀experience/*.json（新建/合并）读轨迹 + 归纳子代理
T12会话状态meta.json（归档/取消/ModelSwitched）—

8.8.3 三条纪律

  1. 绝不跨 IO 持事务——模型、工具、ask、子代理 join 全在 commit() 之外。
  2. 事件在提交后发，且不得驱动任何 IO 长任务；沉淀/检索由 ExecutionLoop 显式调用。
  3. 一个事务只服务一个用例的一次状态转移，不为了"少提交一次"而合并不相关的写。

sequenceDiagram
    autonumber
    participant UI as 外壳

    participant EL as ExecutionLoop

    participant EP as DomainEventPublisher
    participant HI as HumanInteractionPort

    UI->>U2: run(sessionId, text, cancellation)
    U2->>CS: stageAppend(USER)；commit
    U2->>EL: loop(session)

    loop 每轮一次内循环
        EL->>CW: ensureWithinLimit(session)
        CW->>CW: count → 有效上限 → 必要时调模型摘要
        CW->>CS: stageAppend(SUMMARY)；commit
        EL->>RL: runIteration(session, step?)
        RL-->>EL: IterationResult(isConverged, submitted, summary)

        alt 未收敛（撞 maxReActRounds）
            EL->>CS: stageReplace(plan 判败)；commit
            Note over EL: 继续下一轮，无需用户介入
        else 无计划且收敛
            EL-->>U2: 结束
        else 收敛但未提交
            EL-->>U2: 挂起（Attempt 不落终态），等下一次输入
        else 已提交
            EL->>VR: verify(step, attempt)
            alt step 声明了验证
                VR->>VR: 按链序执行（可能调模型 / 调 ask）
                VR-->>EL: VerificationReport
            end
            EL->>CS: stageFact(report?) + stageReplace(plan 状态)；commit
            EL->>EP: publishAfterCommit(StepFailed 等)
            alt PASSED
                Note over EL: 推进到下一条出口判定
            else FAILED
                EL->>HI: ask（人工层，仅 UNDETERMINED 或声明 HUMAN_APPROVAL）
            end
        end
    end

    EL->>EP: publishAfterCommit(PlanCompleted / PlanFailed)
    Note over EL: 计划完结后，由用例显式调用经验沉淀与反馈（不经事件）

8.10错误与恢复策略

情形语义应用层动作聚合落点
工具自身失败（超时/异常/半截）一种工具结果回灌模型，ReAct 继续只追加 TOOL_RESULT
模型不可用（备用链全挂）环境故障RunSession 立即返回；不触发反思/重划/重试不改任何状态；Attempt 不落终态
请求超限业务预算问题强制折叠一次后重试；仍失败按模型不可用处理追加 SUMMARY，不动 plan
用户中断用户主动ask 返回 CANCELLED；当前 attempt 收尾Attempt.outcome = INTERRUPTED（不耗重试）
崩溃残留进程非正常退出StartupReconciler 按下列 5 条补齐视规则而定

StartupReconciler 的 5 条规则

#现场补齐动作
1有 PASSED 报告，但 step 仍 RUNNING / VERIFYING按报告里的 attemptNo 补 markStepSucceeded
2有 FAILED 报告，但 step 仍 RUNNING补 markStepFailed
3流水末尾有 TOOL_REQUEST 无 TOOL_RESULT该 attempt 判失败（按"半截工具调用视为失败"计一次重试）
4会话已被标记删除 / 已存在于 archive/完成删除或归档（幂等）
5budget.json 缺失或损坏重建为 0 并写告警（预算不精确可接受）

技术残留（*.tmp、写了一半的行、未释放的锁）由基础设施层的启动清理处理，不在这里重复。

8.11并发模型

并发点机制约束
用例执行外壳单线程调用；同一 sessionId 同时只有一个 RunSession应用层用 sessionId 做内存互斥，不依赖文件锁
内循环与工具工具严格串行（多个工具调用逐个执行、各自成败）无并发工具调用
子代理SubagentLauncher 内部并行；各自独立超时；join-all子代理不得再开子代理
人机交互HumanInteractionPort 单队列，所有来源排队逐个呈现必须显示来源；cancellation 可唤醒
持久化单写者（InstanceLock）；CommitScope 串行同一时刻只有一个实例写数据目录
UI 更新ProgressPort 单向推送丢弃进度不影响业务
