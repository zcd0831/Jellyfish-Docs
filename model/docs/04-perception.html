第 4 章

感知模块

感知模块只回答一个问题：模型此刻能看到什么。 它把「外部输入」（你、工具结果、模型输出、技能注入）和「运行环境」（全局策略、模型能力、可用工具清单） 变成一条可追溯的上下文流水，长了就折叠。

聚合 2 领域服务 4 端口 1（声明） 领域事件 4 应用事件 1

4.1模块定位与边界

方向内容
本模块聚合Session、RuntimePolicy
本模块声明的端口（由外部实现）ModelInvocationPort（由【行动】ModelInvoker 实现：选模型 / 降级 / 调用 / 计 token / 提供模型档案）
被本模块引用的外部 ID（仅 ID）AgentId、ModelId、ToolId、SkillId
被外部引用的本模块对象Session（被规划持有 sessionId、被行动持有 rootSessionId）、RuntimePolicy（被规划 / 行动 / 记忆只读）
依赖纪律

SystemPromptAssembler 不自己去查工具/技能定义——内容由调用方（外循环 / 应用层）取好作为入参传入； 模型调用一律走 ModelInvocationPort。这样感知模块不依赖任何其它模块的具体实现。

4.4聚合清单

聚合简介不变量
Session 一次会话（可嵌套）的全部上下文事实：记录流水、系统提示词快照、窗口与摘要。由 parentSessionId 组成会话树 ① Record 只追加，被 Attempt.recordRange 引用的记录永不删除/改写；② 快照在会话开启时冻结，运行中不再变；③ Agent 不可切换，Model 可切换；④ 父子会话一致（父取消级联）；⑤ 状态迁移只在 RUNNING / RESUMABLE / ARCHIVED 之间
RuntimePolicy 全局唯一的运行环境策略，只有用户能改，立即生效 ① 全局唯一；② 不进会话冻结快照；③ 参数只能由用户调整

简介
会话族的一个节点。承载"模型能看到的世界"：SystemPromptSnapshot + Record 序列；窗口与用量由 buildContextForLlm() 推导产出，不落库。
关联
agentId、activeModelId（行动）、parentSessionId（自身）、Record（内部）

4.5领域服务清单

服务简介跨模块依赖
SessionFactory 会话的唯一创建入口：创建 Session + Budget（会话族根）+ 冻结快照 + 生成标题；也是子代理会话的唯一创建者 Budget（行动，经应用层/端口）、SystemPromptAssembler

4.8聚合生命周期与规则

4.8.1 Session 的生命周期

诞生变更终结重建
会话开启（用户发起对话）
子代理派遣（spawn_subagents）		 迭代中不断追加 Record；上下文折叠；模型降级；取消 会话封存（ARCHIVED，不可续跑）
会话销毁（物理删除）		 会话续跑（程序重启后按 sessionId 加载为 RESUMABLE）

规则清单（12 条）

  1. 唯一创建入口：只有 SessionFactory 能创建会话；两个触发点——用户发起对话、主会话发起子代理。
  2. 创建时必须指定 agentId 与 modelId（缺省取默认）；Agent 在会话内不可切换，Model 可切换（仅降级）。
  3. 标题：由 LLM 依据首次输入的意图生成；失败则用首句截断兜底。
  4. 快照冻结：SystemPromptSnapshot 在会话开启时生成并冻结（内容快照）；运行中工具/技能定义变更不影响进行中的会话。
  5. 流水只追加：Record 不得修改；被 Attempt.recordRange 引用的区间永不删除、永不改写（本地应用的磁盘控制只能靠归档/导出）。
  6. 会话树：parentSessionId 组树；父会话取消 ⇒ 级联取消所有子会话；子代理不得再开子代理（深度恒为 1）。
  7. 状态：RUNNING（在跑）/ RESUMABLE（持久化、未运行）/ ARCHIVED（封存、不可续跑）。"关终端"不是状态迁移，只是运行态消失。
  8. 销毁：物理删除该会话族的 Record、Plan、Budget；已沉淀的 Experience 保留（记忆模块全局资产）。
  9. 上下文组装（buildContextForLlm(policy)）为三步推导 + 一次降级： ① 取全部 role = SYSTEM 的记录（系统提示词渲染 + SOP 注入 + 工具注入 + 经验注入）； ② 取最新一条 SUMMARY 记录（若有）； ③ 取最近 policy.recordCount 条非 SYSTEM 记录； ④ 降级：若 systemTokens / usedTokens > policy.systemRatioLimit ⇒ 只保留系统提示词快照，丢弃 SOP 与工具注入。
  10. SYSTEM 类不参与淘汰：role = SYSTEM 的记录不被第 ③ 步的"最近 n 条"挤出，只能被第 ④ 步整体裁剪。
  11. 可推导状态不落库：窗口边界与用量都是推导结果，不持久化；会话续跑时重新推导。
  12. 聚合不依赖配置聚合：策略以 ContextWindowPolicy 值对象入参传入，Session 不引用 RuntimePolicy，也不读取任何阈值。

4.8.2 RuntimePolicy 的生命周期

诞生变更终结重建
平台初始化（应用启动载入默认值） 策略调整（用户修改，立即生效） 无（应用生命周期内常驻） 平台初始化

规则清单（8 条）

  1. 全局唯一，只有用户能调整；任何 Agent 都不能覆盖。
  2. 立即生效、不进会话快照：与"工具/技能定义、系统提示词在会话开启时冻结"形成对照。
  3. 反思阈值与最大重试独立配置：reflectionThreshold > maxRetries ⇒ 永不反思。
  4. 唯一硬闸 maxReActRounds：按"自上次用户输入以来的连续轮数"计，用户介入即重置。
  5. 信任清单：工具级粒度，语义 = 免审批，可覆盖不可逆工具；未命中且工具非只读 ⇒ 执行前放行审批。
  6. 预算参数：单位 token、只预警不中断、同一会话族只报一次。
  7. 变更即通知：adjust() 成功后 raise PolicyAdjusted，避免其它模块各自缓存常量快照。
  8. 聚合不变量不依赖自身取值：策略只改变"外循环选择哪条迁移"，不改变任何聚合的合法状态迁移。

4.9.2 ContextWindowService.ensureWithinLimit(session)

阻塞式地保证本次模型调用前上下文不超限；必要时折叠。

sequenceDiagram
    autonumber
    participant APP as 外循环 / 内循环
    participant CW as ContextWindowService
    participant RP as RuntimePolicy
    participant PORT as ModelInvocationPort（行动）
    participant S as Session

    APP->>CW: ensureWithinLimit(session)
    CW->>RP: summarizationTokenThreshold / contextWindowRecordCount / systemRecordRatioLimit
    CW->>PORT: describe(activeModelId) 取模型档案
    CW->>CW: inputCeiling = min(策略阈值, maxInputTokens − inputSafetyMargin)
    CW->>S: buildContextForLlm(ContextWindowPolicy)
    S-->>CW: ContextWindow（窗口记录 + ContextUsage）
    alt usage.usedTokens ≤ inputCeiling
        CW-->>APP: 直接返回
    else 超限
        CW-->>APP: 应用事件 SummarizationStarted（界面显示“压缩中”）
        CW->>CW: 选出窗口外的旧记录作为待摘要区间
        CW->>PORT: invoke(摘要请求)<br/>提示词不进 Record
        PORT-->>CW: 摘要文本（token 记账到会话族根）
        CW->>S: markSummarized(summary)
        S->>S: appendRecord(SUMMARY)
        S-->>CW: raise SummarizationCompleted
        CW-->>APP: 返回（下一次推导即得到新窗口）
    end

要点（8 条）

  1. 压缩阻塞：期间不发起新的模型调用（摘要那一次除外）。
  2. 摘要提示词用户不可见、且不进 Record；用户只能看到压缩状态与压缩结果（SUMMARY 记录）。
  3. 摘要由当前会话模型生成，token 记到会话族根。
  4. 不存在"滑窗"这个动作：窗口由 buildContextForLlm() 每次推导，追加 SUMMARY 后自然生效；SYSTEM 占比在推导的第 ④ 步处理。
  5. 有效上限 = min(summarizationTokenThreshold, maxInputTokens − inputSafetyMargin)（inputSafetyMargin 默认 10000）。语义是"安全余量"（抵御估算偏差、系统提示临时插入），不是输出预留——输入与输出是两个独立上限（maxOutputTokens 单独生效）。
  6. 计量口径唯一：本服务不自己实现 tokenizer，一律经 ModelInvocationPort 计量，保证与真实计费一致。
  7. 用量随请求传下去：推导出的 ContextUsage.usedTokens 由调用方填入 ModelInvocationRequest.estimatedPromptTokens，供行动侧硬校验；行动不得反向回查 Session。
  8. 承接"请求超限"的补充折叠：行动 ModelInvoker 抛「请求超限」时，外循环调本服务强制折叠一次再重试；不消耗重试名额；仍超限则同"模型不可用"返回并提示。

4.9.5 Session.buildContextForLlm(policy) → ContextWindow

把"记录流水"推导为"本次发给模型的窗口 + 用量"。它是纯函数式的推导行为：不改状态、不落库、不读配置聚合。

flowchart TD
    A[入参：ContextWindowPolicy] --> B[① 取全部 role=SYSTEM 记录<br/>系统提示词渲染 / SOP 注入 / 工具注入 / 经验注入]
    B --> C[② 取最新一条 SUMMARY 记录（若有）]
    C --> D[③ 取最近 policy.recordCount 条<br/>非 SYSTEM 记录]
    D --> E[④ 计算 usedTokens / systemTokens / summaryTokens]
    E --> F{systemTokens / usedTokens<br/>> policy.systemRatioLimit ?}
    F -- 否 --> H[输出 ContextWindow]
    F -- 是 --> G[退化为：只保留系统提示词快照<br/>丢弃 SOP 与工具注入] --> H

四条 DDD 约束

约束体现
聚合方法不读其它聚合策略以 ContextWindowPolicy 值对象入参传入，Session 不引用 RuntimePolicy
可推导状态不落库窗口边界与用量不持久化，续跑时重算
值对象不可变ContextWindow / ContextUsage / ContextWindowPolicy 生成后不可改
无副作用只读 records 与入参，不改任何聚合状态；摘要写入由 markSummarized() 单独完成
与折叠的分工（不要混）

buildContextForLlm 只负责"算"；ContextWindowService 负责"决定要不要折"；Session.markSummarized() 负责"把摘要写进流水"。

步骤重试失败后新建 Attempt；达阈值则产生 Reflection
