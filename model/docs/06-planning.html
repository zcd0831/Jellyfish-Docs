第 6 章

规划模块

规划模块回答三个问题：想怎么做（Plan）→ 做到哪一步（PlanStep / Attempt）→ 算不算做成了（VerificationReport）。 它是唯一有权推进计划状态机的模块；感知、记忆、行动三个模块只被它调用或引用。

聚合 2 领域服务 4 领域事件 5 系统心脏

6.1模块定位与边界

方向内容
本模块聚合Plan、VerificationReport
被本模块引用的外部聚合（仅 ID / 只读）Session、RuntimePolicy（感知）、Experience（记忆）、Reflection（记忆）
本模块调用的外部对象应用层：ContextWindowService（感知）、ToolExecutor、BudgetService（行动）、ExperienceRetriever / ExperienceDistillationService / ExperienceFeedbackService（记忆）
本模块对象所在的层领域层：Plan、VerificationReport、PlanFactory、VerificationChain；应用层：ExecutionLoop、ReActLoop、VerificationRunner（见 第 8 章）
被外部引用的本模块对象Plan（被感知模块的会话持有引用）、VerificationReport / Reflection-ID（被 Attempt 引用）
归属约定：聚合不变量不得依赖 RuntimePolicy

凡涉及阈值 / 上限 / 开关的判断（重试上限、重划上限、ReAct 轮次、窗口条数、信任清单等）， 一律由外循环在调用聚合前后判定；聚合只保证状态机自身的合法迁移。详见 6.8.1 末尾「由外循环保证的约束」。

6.4聚合清单

聚合简介不变量
Plan 大模型通过 generate_plan 产出的一次可执行工作分解；严格串行推进，完成即固化 ① steps 至少 1 个；② 同一时刻至多一个 RUNNING step（严格串行）；③ SUCCEEDED 的 step 不可再变更；④ Replan 只能替换未执行尾部；⑤ 单写者，无需乐观锁
VerificationReport 外循环对某次 Attempt 的判定结论，只追加、不可变 ① 生成后不可修改；② 三态结论；③ 只保留失败层与失败原因

6.4.1 Plan

简介
一次任务的工作分解；由 generate_plan 工具触发 PlanFactory 创建；步骤严格串行推进；每次重划产生新一代。
关联
sessionId → Session（感知）、assignedExperienceIds → Experience（记忆）、VerificationReportId / ReflectionId（本模块 / 记忆）

6.4.2 VerificationReport

简介
串行责任链按 step 声明过滤后的判定产物；四层：DETERMINISTIC → ENV_FEEDBACK → LLM_JUDGE → HUMAN_APPROVAL，短路。
不变量
结论三态；只保留失败层与失败原因；不可变。
关联
被 Attempt.verificationReportId 引用；被反思与经验沉淀读取。

6.4.3 关于 RuntimePolicy（归属【感知】模块）

RuntimePolicy 是运行环境的一部分（全局唯一、只有用户能改、立即生效），因此归属【感知】模块，不在本模块内。 本模块对它是只读依赖：只在调用侧读取，从不写入聚合不变量。

参数组参数主要消费者

6.5领域服务清单

服务层简介跨模块依赖
SessionRunner扩展点交付一轮运行的统一入口；默认实现是 ExecutionLoop，插件可实现自己的循环（L3，experimental）RunContext（把端口与上下文交给实现方）
ExecutionLoop应用SessionRunner 的默认实现：会话执行的总驱动（do-while）：每轮算上下文 → 取 step → 跑一次内循环 → 验证 → 按三条出口推进ContextWindowService、ReActLoop、VerificationRunner、经验三件套

VerificationChain领域纯规则：requiredVerifications → 有序层列表；短路与三态合并无

6.8聚合生命周期与规则

6.8.1 Plan

诞生变更终结重建
计划诞生（PlanFactory 校验通过，replanGeneration = 0） 步骤启动、步骤提交验收、步骤固化 / 判败 / 中断、步骤重试、计划重划、经验分配 计划完结（COMPLETED / FAILED） 会话续跑（按 planId 加载；RUNNING step 的 attempt 继续）

规则清单（9 条）

  1. 诞生：Plan 只能由 generate_plan 工具触发创建，不由用户直接构造。校验项：可解析、steps 非空、引用的工具/技能都在 AgentDefinition 绑定内、步骤依赖无环、规模与预算不荒谬。校验失败 ⇒ 作为工具失败结果回灌模型，不消耗 step 重试。
  2. 串行：同一时刻至多一个 RUNNING step，getCurrentStep() 返回唯一当前步。
  3. 验证声明：requiredVerifications 由模型在生成计划时声明，不强制；为空 ⇒ 该 step 不验证、不产生验证报告，submit_step 提交即完成。
  4. 固化：SUCCEEDED 后 finalOutput / finalVerificationReportId / attempts 不再变更。
  5. 重划：applyReplan() 只能替换未执行的尾部 step；被替换者置 SUPERSEDED 并保留（可审计），replanGeneration + 1。聚合只保证「尾部替换 + 代次递增」这次迁移合法；「还能不能再重划、用尽后判失败」由外循环保证。
  6. 结局：COMPLETED / FAILED 都是终态；两者都会触发经验沉淀；FAILED 后循环收敛退出。
  7. 单写者：执行严格串行 + 单一调度者，聚合不设乐观锁版本号。
  8. 经验分配：计划诞生时与每次重划后，由 ExperienceRetriever 为（新产生的）step 分配 assignedExperienceIds。
  9. 环境故障不改状态：模型不可用时外循环直接返回，Plan 保持 EXECUTING、step 保持 RUNNING、Attempt 不结束；既不判 FAILED 也不判 INTERRUPTED，不消耗重试名额，也不触发反思/重划（否则递归撞死）。

由外循环保证的约束（不在聚合不变量内）

约束由谁保证实现方式
有效重试次数不超过 maxRetriesExecutionLoop超限时不再新建 Attempt，改走「重划或 terminate()」
是否开启反思ExecutionLoop读 reflectionThreshold（> maxRetries 即永不反思），决定回注原始失败原因还是反思结论
重划次数不超过 maxReplanGenerationExecutionLoop超限时调用 Plan.terminate(reason)（聚合只执行终止，不判断该不该终止）
单次迭代 ReAct 轮数不超过 maxReActRoundsReActLoop超限时把本次 attempt 判为失败并返回外循环
验证链各层是否启用、信任清单是否放行VerificationRunner读 requiredVerifications 与 trustedToolIds

原则：配置变化不改写聚合的合法状态迁移，只改外循环选择哪条迁移。

6.8.2 VerificationReport

诞生变更终结重建
步骤提交验收（该 step 至少声明一种验证类型时） 无（不可变） 随会话销毁而删除；SUCCEEDED step 的报告随计划固化而永久只读 会话续跑（按 ID 读取，参与反思与沉淀）

四层的判定口径

层验什么判定方式
DETERMINISTIC非空、数据结构、边界与阈值纯代码：提交摘要非空；摘要形似 JSON 时必须能解析；声明的 artifact 结构/数量按 step 声明的边界检查
ENV_FEEDBACK外部系统的实际返回预留钩子：step 若声明"调用某系统 API 推送/变更"，调用后校验其返回；本期无此类 step，钩子未配置时返回 UNDETERMINED（不假装通过）
LLM_JUDGE自然语言类产出（报告、文章）或无法写死规则的结果内置裁判代理，输入三要素：goal（原定目标）、expectedOutcome（结果期望）、verificationCriteria（验证标准）+ 执行结果摘要。不得把执行者的推理过程交给裁判（父子包庇：谁执行谁判 = 自证）
HUMAN_APPROVAL高危操作（转账、删库、发正式邮件）或模型无法判定的节点预留钩子：ask_user，同意 ⇒ PASSED；不同意 + 必填原因 ⇒ FAILED

父子包庇：裁判只拿到"目标 / 期望 / 标准 / 结果"，拿不到子步骤自述的推理链；且裁判用独立代理（builtin.judge）的提示词，不复用执行代理的身份。

规则清单（7 条）

  1. 触发：只有 submit_step 提交后、且 requiredVerifications 非空时才生成。
  2. 链序：固定 DETERMINISTIC → ENV_FEEDBACK → LLM_JUDGE → HUMAN_APPROVAL，按 step 声明过滤后串行执行、短路。
  3. 三态：PASSED / FAILED / UNDETERMINED；UNDETERMINED ⇒ 转人工（升级到人工层 / ask_user）。
  4. 内容：只保留失败层（failedType）与失败原因（failureReason）；不做逐层留痕、不保留期望 vs 实际。
  5. 人工层：返回"同意 / 不同意 + 必填原因"；不同意 ⇒ 该 step 带着该原因重试；结果并入同一份报告。
  6. 边界：工具自身失败（超时 / 异常 / 半截）不是验证失败，它只是"一种工具结果"，回灌给模型继续 ReAct。
  7. 不可变：生成后任何角色不得修改。

6.8.3 关于 RuntimePolicy（归属【感知】模块）

本模块不持有该聚合，它的生命周期与规则见第 4 章。 本模块只在调用侧读取「重试与反思」一组参数，且不写入任何聚合不变量（见 6.8.1）。

                    OL->>RP: needsReflection(retryCount)
                    alt 达反思阈值（且未超最大重试）
                        Note over OL: 反思子代理 → Reflection（记忆）→ 结论作为失败原因回注
                    else 未达阈值
                        Note over OL: 直接回注验证失败原因
                    end
                else UNDETERMINED
                    Note over OL: 转人工（HUMAN_APPROVAL → ask）
                end
            end
        else 未提交（收敛但无 submit_step）
            Note over OL: attempt 不结束、step 保持 RUNNING、不消耗重试；等用户下一次输入续跑
        end
    end

经验检索与沉淀由 ExecutionLoop 在计划诞生 / 计划完结时显式调用（不经领域事件），详见 第 8 章 8.8。

关键分支

条件结果
无 Plan 且内循环收敛本次交互结束，会话停在原处（会话没有状态，D22）
内循环里 generate_plan 成功本轮收敛后，下一次迭代 hasExecutablePlan() 为真，转入计划执行
计划 COMPLETED再跑一轮自由内循环，由模型产出最终答复（这就是"结论交付"）；完结时由 PlanCompletionCurator 一次判定产出「经验? / 技能?」（用过技能 ⇒ 判改进；没用过 ⇒ 判沉淀）
计划 FAILED（外循环判定重划用尽 → terminate()）循环收敛退出，触发沉淀
模型不可用（ModelInvoker 抛出）run() 立即返回，不迁移任何聚合状态、不消耗重试、不触发反思/重划；step 保持 RUNNING、Attempt 不结束；仅提示用户（不自动重试）
收敛但未提交本轮 run() 直接返回；Attempt 挂起（不落终态）、不消耗重试；plan 仍 EXECUTING、step 仍 RUNNING；用户下次输入后取同一步、同一 Attempt 继续（recordRange 继续延伸）
撞 maxReActRounds（未收敛）该 Attempt 判失败 → 重试 / 反思 / 重划 → 自动继续下一轮，不需要用户介入
请求超限（ModelInvoker 抛出）外循环调 ContextWindowService 强制折叠一次后重试；不消耗重试名额、不改聚合状态；仍超限则同「模型不可用」返回并提示

6.9.2 ReActLoop.runIteration(Session, PlanStep)（应用层）

跑一次 ReAct 迭代；唯一出口是"模型不再调用工具"。它不判断 step 是否完成，只识别模型是否调用了 submit_step。

sequenceDiagram
    autonumber
    participant IL as ReActLoop
    participant S as Session（感知）
    participant TE as ToolExecutor（行动）
    participant BS as BudgetService（行动）
    participant RP as RuntimePolicy（感知）

    IL->>S: buildContextForLlm(ContextWindowPolicy)
    S-->>IL: ContextWindow
    IL->>RP: maxReActRounds
    loop 直到模型不再调工具 或 达到 maxReActRounds
        IL->>TE: execute(session, tool, args)
        TE-->>IL: 工具结果（成功/失败都只是“结果”）
        IL->>S: appendRecord(TOOL_REQUEST)
        IL->>S: appendRecord(TOOL_RESULT, payload)
        IL->>BS: recordUsage(会话族根, tokens)
        alt 工具 == submit_step
            Note over IL: 记录 submitted = true、submittedSummary；本轮收敛
        else 工具 == ask_user
            Note over IL: 阻塞等待用户回答（同一 ReAct 循环内）
            IL->>S: appendRecord(TOOL_RESULT, 用户回答)
        else 工具 == load_skill
            Note over IL: 把返回的 SOP 注入为一条 role=SYSTEM 的 Record
        end
    end
    alt 达到 maxReActRounds
        Note over IL: attempt 判失败（交回外循环）
    else 模型不再调工具
        IL-->>IL: IterationResult(isConverged = true, submitted, submittedSummary, round)
    end

6.9.3 VerificationRunner.verify(PlanStep, Attempt)（应用层）

链序与短路/三态合并的规则由领域服务 VerificationChain 给出；VerificationRunner 只负责按序真的执行。

按声明过滤后的固定链序执行验证，产出不可变报告。

sequenceDiagram
    autonumber
    participant VS as VerificationRunner
    participant PS as PlanStep
    participant RP as RuntimePolicy（感知）
    participant VR as VerificationReport

    VS->>PS: requiredVerifications
    VS->>RP: trustedToolIds / 阈值
    loop 固定链序：DETERMINISTIC → ENV_FEEDBACK → LLM_JUDGE → HUMAN_APPROVAL
        alt step 未声明该层
            Note over VS: 跳过
        else 已声明
            VS->>VS: 执行该层验证
            alt 通过
                Note over VS: 继续下一层
            else 不通过
                VS->>VR: 创建报告（FAILED, failedType, failureReason）
                VR-->>VS: raise VerificationRejected
                Note over VS: 短路返回
            else 无法判定
                VS->>VR: 创建报告（UNDETERMINED）
                Note over VS: 转人工
            end
        end
    end
    alt 全部通过
        VS->>VR: 创建报告（PASSED）
    end

6.9.4 PlanFactory.create(Session, planArgs)（领域）

把大模型产出的计划草案变成合法的 Plan 聚合；校验失败即工具失败。

flowchart TD
    A[接收 generate_plan 的入参] --> B{可解析?}
    B -- 否 --> X[返回工具失败结果给模型<br/>不消耗 step 重试]
    B -- 是 --> C{steps 非空?}
    C -- 否 --> X
    C -- 是 --> D{引用的工具/技能<br/>都在 Agent 绑定内?}
    D -- 否 --> X
    D -- 是 --> E{步骤依赖无环?}

    E -- 是 --> F{规模与预算合理?}
    F -- 否 --> X
    F -- 是 --> G[创建 Plan<br/>status = EXECUTING<br/>replanGeneration = 0]
    G --> H[raise PlanCreated]
    H --> I[ExperienceRetriever 为各 step 分配经验]
    I --> J[返回“计划已创建”给模型]
