第 7 章

记忆模块

记忆模块回答一个问题：学到的东西怎么留下来、下次怎么用上。 它持有两类知识资产：陈述性知识（Experience：踩过的坑）与 程序性知识（SkillDefinition：怎么做好一件事的 SOP）， 以及两者之间的蒸馏中间态（Reflection）。

7.1模块定位与边界

方向内容
本模块聚合Experience、Reflection、SkillDefinition
本模块端口无。检索/归纳所需的子代理能力由应用层 SubagentLauncher 提供；SOP 渲染由基础设施 SkillSopProvider 提供
被本模块引用的外部 ID（仅 ID）PlanId、StepId（规划）、RecordRange / SessionId（感知）
被外部引用的本模块对象ExperienceId（规划 PlanStep.assignedExperienceIds）、ReflectionId（规划 Attempt.reflectionId）、SkillId（行动 AgentDefinition.skillIds）、RuntimePolicy 中的经验参数（只读）
本模块对象所在的层领域层：Experience、Reflection、SkillDefinition（含其规则）；应用层：检索 / 沉淀 / 反馈三个服务；基础设施层：SkillSopProvider
依赖纪律：记忆不回写别人的聚合
  • 需要"把经验分配给 step"时，它只返回分配结果（Map<StepId, List<ExperienceId>>），由【规划】的 Plan.assignExperiences() 自己改状态；
  • 需要"读本 Plan 的执行事实"时，由调用方组装 DistillationInput 值对象传入，而不是让记忆去遍历 Plan 聚合；
  • 需要"读原始对话"时，按 RecordRange 只读 Session.Record（含子会话）—— 读操作不算依赖，且绝不追写。

7.4聚合清单

聚合简介不变量
Experience 全局经验库的一条经验：适用场景 + 教训 + 置信度 + 使用统计。只有一种经验：失败后翻盘的反思教训 ① 置信度恒在 [0,1]；② 不绑定任何 Agent / 工具 / 技能；③ ARCHIVED 后不再参与检索；④ 容量不得超上限
Reflection 一次失败的反思结论，是"经验蒸馏"的中间态与"重试回注"的素材 ① 生成后不可变；② 一条 reflection 归属唯一 (planId, stepId, attemptNo)
SkillDefinition 程序性知识：描述 + 触发条件 + SOP 模板；纯提示词资产，不携带工具 ① 只有 ACTIVE 才进入会话快照；② SOP 不得引用未绑定的工具；③ 不含任何工具 ID 列表

7.4.1 Experience

沉淀于计划完结时；检索于计划诞生 / 重划时；语义不绑定任何维度，全局共享。被 PlanStep.assignedExperienceIds 引用（规划）。

7.4.2 Reflection

重试达阈值后由反思子代理产出；双消费者：回注本 step 的下一次 attempt（作为失败原因）、作为经验沉淀素材。被 Attempt.reflectionId 引用（规划）。

7.4.3 SkillDefinition

渐进披露：系统提示只挂 name + description；模型调 load_skill 才注入 SOP 全文（role = SYSTEM 的 Record）。被 AgentDefinition.skillIds 引用（行动）；由基础设施 SkillSopProvider 渲染。

7.5领域服务清单

服务层简介依赖

7.7领域事件

事件谁发出什么时候谁关心

应用事件 ExperienceDistillationFinished：一次沉淀流程跑完（可能产出 0 条，例如全库已有等价经验且合并后无变化）。它不属于任何聚合的状态转换。

本模块订阅：PlanCreated / PlanFailed / PlanCompleted（规划）—— 前者触发检索分配，后两者触发沉淀；PolicyAdjusted（感知）—— 刷新容量、Top-N、置信度步长等读取缓存。

7.8聚合生命周期与规则

7.8.1 Experience

诞生变更终结重建
计划完结（PlanCompleted / PlanFailed 后由归纳子代理产出） reinforce / penalize（step 结束回写）、合并（语义重复时提置信度）、archive（置信度 < 阈值或容量淘汰） ARCHIVED（不再参与检索，保留供审计） 应用启动时载入

规则清单（11 条）

  1. 只有一类经验：失败后翻盘的反思教训；终局失败（PlanFailed）的反思也沉淀，只是初始置信度低。
  2. 沉淀时机：只在计划完结时发生，不在失败瞬间、不在 step 结束时发生。
  3. 每 Plan 条数上限：experiencePerPlan（用户可调，默认 1）。
  4. 去重：与库内经验语义重复 ⇒ 合并 + 提置信度，不新建。
  5. 置信度：范围 [0,1]；初值 experienceInitialConfidence（0.5）；reinforce +step、penalize −step（experienceConfidenceStep = 0.1）；低于 experienceRetireThreshold（0.2）淘汰。
  6. 容量与淘汰：总量上限 experienceCapacity；超限时优先淘汰"最早且最少被使用"（createdAt 升序 + appliedCount 升序）。
  7. "被应用"的判定：不靠"是否注入"猜测，而靠检索子代理的标注建议。
  8. 回写不对称（有意为之）：成功 ⇒ 只奖励"被建议的"；失败 ⇒ 惩罚"本次注入的全部"（宁可错杀，防止垃圾经验滞留）。
  9. 事件：新建 ⇒ ExperienceCreated；reinforce() 成功 ⇒ ExperienceReinforced；penalize() 成功 ⇒ ExperiencePenalized；语义重复的合并归入 ExperienceReinforced。
  10. 不绑定维度：不绑 Agent、不绑工具、不绑技能 —— 全局单一库，跨代理共用。
  11. 命中检测：检索走语义筛选，不做关键词匹配；经验只存"适用场景"自然语言 + 教训正文。

7.8.2 Reflection

诞生变更终结重建
步骤重试（有效重试次数达 reflectionThreshold） 无（不可变） 随会话销毁而删除（其价值已由 Experience 承接） 会话续跑时按 ID 读取

规则清单（6 条）

  1. 触发条件：reflectionThreshold ≤ maxRetries 且有效重试次数达到阈值；reflectionThreshold > maxRetries ⇒ 永不反思（直接回注验证失败原因）。
  2. 产者：反思子代理（BUILT_IN Agent，prompt 固定、工具集写死）。
  3. 双消费者：① 作为下一次 attempt 的失败原因回注（Reflexion）；② 作为经验沉淀素材。
  4. 不可变：生成后任何角色不得修改。
  5. 归属唯一：一条 reflection 对应唯一的 (planId, stepId, attemptNo)。
  6. 不消耗重试名额：反思本身不是一次 attempt。

7.8.3 SkillDefinition

诞生变更终结重建
平台初始化（内置技能）/ 用户创建 updateSop、activate / deprecate DEPRECATED（不再进入新会话快照） 应用启动时载入

规则清单（6 条）

  1. 纯提示词资产：只有描述、触发条件、SOP 模板；不含工具依赖（toolIds 已删除）。
  2. 渐进披露：系统提示只挂 name + description；SOP 正文只能通过 load_skill 注入。
  3. 注入形态：SOP 注入为一条 role = SYSTEM 的 Record，此后不参与滑窗（除非 SYSTEM 占比超限被整体裁剪）。
  4. 只有 ACTIVE 技能进入新会话快照。
  5. 一致性：SOP 正文里提到的工具必须在 AgentDefinition.toolIds 内；否则由感知组装快照时告警（不阻断，模型看得到提示但调不动工具）。
  6. 技能不自动激活：triggerCondition 只是给模型看的判断依据，是否加载由模型调 load_skill 决定。

7.9领域服务的具体操作

7.9.1 ExperienceRetriever.retrieveAndAssign(RetrievalInput)

计划诞生 / 每次重划后，为各 step 分配经验。它只返回分配结果，不写 Plan。

sequenceDiagram
    autonumber
    participant OL as ExecutionLoop（规划）
    participant R as ExperienceRetriever
    participant RP as RuntimePolicy（感知）
    participant E as Experience 库
    participant SL as SubagentLauncher（应用层）

    OL->>R: retrieveAndAssign(RetrievalInput{planId, steps})
    R->>RP: experienceTopN / experienceCapacity
    R->>E: 取全部 status = ACTIVE 的经验
    E-->>R: 经验列表（适用场景 + 教训）
    R->>SL: 跑一次内置检索代理（整库 + 各 step 描述）
    SL-->>R: 每个 step 的建议经验（≤ Top-N）
    R->>R: 汇总 Assignment（Map‹StepId, List‹ExperienceId››）
    R-->>OL: Assignment
    OL->>OL: Plan.assignExperiences(stepId, ids)

要点

  1. 全库交子代理语义筛选，不做关键词预筛（关键词在中文/领域术语上漏召严重）。
  2. 只在计划诞生与计划重划两个时点发生；无 Plan 的自由 ReAct 不检索（经验按 step 分配）。
  3. 检索子代理的标注建议同时是"被应用"的判定依据（供 7.9.3 回写）。

7.9.2 ExperienceDistillationService.distill(DistillationInput)

计划完结时把"执行事实"蒸馏成一条经验。

flowchart TD
    A[PlanCompleted / PlanFailed] --> B[外循环组装 DistillationInput<br/>sessionId + goal + 结局 +<br/>每步 RecordRange / 子会话 / 失败原因 / 反思结论]
    B --> C[本服务按 RecordRange 只读 Session.Record<br/>（含 childSessionIds 子会话记录）]
    C --> D[素材裁剪：仅保留“失败后翻盘”的尝试及其成功尝试区间<br/>超长区间按截断阈值裁剪]
    D --> E{有可用素材?}
    E -- 无 --> X[raise ExperienceDistillationFinished<br/>本次不产出]
    E -- 有 --> F[拼成消息，交归纳子代理<br/>产出候选经验：适用场景 + 教训]
    F --> G[与库内经验语义比对]
    G --> H{语义重复?}
    H -- 是 --> I[合并：保留更清晰表述 + 提置信度<br/>raise ExperienceReinforced]
    H -- 否 --> J{已达 experienceCapacity?}
    J -- 是 --> K[按“最早 + 最少被使用”淘汰后新建]
    J -- 否 --> L[新建 Experience]
    K --> M[raise ExperienceCreated]
    L --> M
    I --> N[raise ExperienceDistillationFinished]
    M --> N

要点

  1. 素材口径：DistillationInput 由外循环组装（记忆不遍历 Plan 聚合）；但它带轨迹区间，由本服务从 Session.Record 只读取出原始对话（含子会话），拼成消息交给归纳子代理。
  2. 读而不写：读 Session 是只读操作，不得向会话追写任何记录；因此不需要新端口，也不破坏"不回写别人聚合"的纪律。
  3. 素材裁剪：原始轨迹可能极长，只保留"失败后翻盘"的 attempt 与其成功的后继区间；单个区间超过截断阈值时截短（否则归纳子代理会直接撞上下文上限）。
  4. 每个 Plan 最多沉淀 experiencePerPlan 条；产出 0 条是合法结果。
  5. 终局失败也沉淀：PlanFailed 同样触发，初始置信度按配置（偏低）。

7.9.3 ExperienceFeedbackService

step 结束时把结果回写到经验统计（奖惩不对称）。

sequenceDiagram
    autonumber
    participant OL as ExecutionLoop（规划）
    participant F as ExperienceFeedbackService
    participant E as Experience
    participant RP as RuntimePolicy（感知）

    OL->>F: onStepSucceeded(FeedbackInput{stepId, injected, suggested})
    F->>RP: experienceConfidenceStep
    loop 仅“被建议的”经验
        F->>E: reinforce()
        E->>E: confidence += step（上限 1）
        E->>E: appliedCount += 1
    end

    OL->>F: onStepFailed(FeedbackInput{...})
    loop 本次“注入的全部”经验
        F->>E: penalize()
        E->>E: confidence −= step（下限 0）
        alt confidence < experienceRetireThreshold
            E->>E: archive()
        end
    end

要点：失败惩罚不做相关性归因（有意为之：宁可错杀）；置信度跌到阈值以下即 archive()，不再参与检索。

7.9.4 SkillSopProvider.sop(skillId)（基础设施，被 load_skill 调用）

sequenceDiagram
    autonumber
    participant TE as ToolExecutor（行动）
    participant L as SkillSopProvider（基础设施）
    participant SK as SkillDefinition
    participant IL as ReActLoop（规划）

    TE->>L: handle({skillName})
    L->>SK: 按 name 查 ACTIVE 技能
    alt 未找到或非 ACTIVE
        L-->>TE: 返回“技能不可用”结果
    else 找到
        L->>SK: renderDetailedSop(变量)
        SK-->>L: SOP 全文
        L-->>TE: SOP 文本
        TE-->>IL: 工具结果
        IL->>IL: 追加一条 role = SYSTEM 的 Record（不滑出）
    end

要点：SkillSopProvider 只负责"读文件 + 渲染"；把它注入成 SYSTEM Record 是内循环的职责（记忆模块不写别人的会话）。

节点含义
平台初始化应用启动：载入 RuntimePolicy，播种内置 Agent / 内置工具 / 内置技能
策略调整用户修改 RuntimePolicy，立即生效
会话开启创建 Session + Budget（会话族根）+ 冻结提示词快照 + 生成标题
会话续跑程序重启后 resume：加载 Session / Plan / Budget；半截工具调用视为失败
子代理派遣spawn_subagents 内部创建完整子会话
计划诞生PlanFactory 创建 Plan（并触发经验分配）
步骤启动取当前 step，创建 Attempt（开区间）
步骤提交验收submit_step → 触发验证 / 或免验证直接完成
步骤固化 / 判败 / 中断step 的三种结束：SUCCEEDED / FAILED / INTERRUPTED
步骤重试失败后新建 Attempt；达阈值则产生 Reflection
计划重划replanGeneration + 1，未执行 step 置 SUPERSEDED 并重新分配经验
计划完结COMPLETED / FAILED，触发经验沉淀
上下文折叠token 超阈值 → 生成 SUMMARY → 窗口收窄
模型降级故障命中备用模型链
会话封存 / 会话销毁归档（不可 resume）/ 物理删除（连带 Record / Plan / Budget，经验保留）
