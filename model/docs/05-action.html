第 5 章

行动模块

行动模块回答三个问题：能做什么（工具）→ 用什么做（模型 / 供应商）→ 谁在做、花多少钱（代理 / 预算）。 它是唯一有权对外部世界产生副作用的模块（调工具、调模型、扣 token），也是唯一持有凭据的模块。

聚合 5 领域服务 3 端口 1 实现 · 1 声明 领域事件 2

5.1模块定位与边界

方向内容
本模块聚合ToolDefinition、Provider、Model、AgentDefinition、Budget
本模块对象所在的层领域层：5 个聚合及其规则；应用层：ToolExecutor、BudgetService；基础设施层：ModelInvoker（SkillSopProvider 是记忆模块声明的端口，由基础设施实现，不属于本模块对象）
被本模块引用的外部 ID（仅 ID）SessionId（感知，Budget.sessionFamilyRootId、子会话创建）、SkillId（记忆，仅作为绑定 ID）
被外部引用的本模块对象RuntimePolicy 的读取者（感知持有）、ToolId / ModelId / AgentId 被各模块引用
依赖纪律

本模块不自行实现任何端口。ModelInvocationPort 由基础设施 ModelInvoker 实现； load_skill 的 SOP 读取由基础设施 SkillSopProvider 实现；其余四个内置工具的处理器本来就在应用层。 行动模块因此对"文件、网络、终端"零依赖。

5.4聚合清单

聚合简介不变量
ToolDefinition 一个可被模型调用的动作定义：schema、来源、副作用等级、自带超时 ① 入参必须能通过 inputSchema 校验；② INTERNAL 工具只能指向内部处理器；③ 元数据 / 状态变更后 raise ToolDefinitionUpdatedEvent（运行中会话不订阅，因快照已冻结）
Provider 模型供应商：端点与凭据的唯一持有者 ① 凭据只存在于 Provider；② 一个 Provider 可对应多个 Model
Model 可调用的具体模型：上下文上限、能力标签、状态 ① status = ACTIVE 才能被调用；② 能力标签用于 spawn_subagents 时的模型匹配；③ 不承载价格（金额概念已删除）
AgentDefinition 代理身份与能力边界：基础 prompt + 绑定工具 + 绑定技能 ① 内置代理的 prompt 不可编辑；② 业务代理的工具 / 技能全部由用户绑定，不强制；③ 会话内 Agent 不可切换
PluginManifest 一个插件的授权意图：它带来哪些工具、能替换哪些端口、用户勾了哪些 ① id 必须等于 jar 内 Plugin-Id；② grantedCapabilities ⊆ declaredCapabilities；③ 同一端口至多一个启用者（跨插件校验在应用层）；④ apiVersion 不符即不能安装或启用；⑤ 不存"已加载/失败"——那是进程内事实
Budget 会话族的 token 台账与一次性预警标记 ① 一个会话族一个 Budget，以根 sessionId 标识；② 只累加、不预留、不分配额度、不中断；③ warned 一旦置真不再预警

5.4.1 ToolDefinition

模型可以调用的一个动作；source 决定谁来执行。AgentDefinition.toolIds 决定"本代理能用哪些"；RuntimePolicy.trustedToolIds 决定"哪些免审批"。

5.4.2 Provider / Model

  • 凭据只在 Provider；Model 通过 providerId 关联。
  • protocol 决定线协议：OPENAI_CHAT（缺省；OpenAI / DeepSeek / Kimi / MiniMax 等兼容端点）、ANTHROPIC_MESSAGES、GEMINI。厂商差异（baseUrl、模型名）是数据，协议差异是适配器——新增厂商只加 providers/*.json，不改代码。
  • capabilities 的唯一消费者是 LLM：spawn_subagents 指定子代理模型时，按能力匹配（如需要 vision / function calling）。
  • 模型故障 → ModelInvoker 按 RuntimePolicy.modelFallbackChain 自动降级，并让 Session.switchModel() raise ModelSwitched。

5.4.3 AgentDefinition

  • source = BUILT_IN：反思 / LLM 裁判 / 经验检索 / 经验归纳，prompt 不可编辑、工具集写死。
  • source = USER_DEFINED：prompt 可改，工具与技能由用户自行绑定（不强制任何内置工具）。
  • 状态动词统一：submit / activate / deprecate。

5.4.4 Budget

  • 单位 token，不换算金额。
  • 只预警、不中断：达到 budgetWarnRatio → 外循环经 ask_user 询问是否继续；同一会话族只报一次。
    budgetLimitTokens 是会话族的总额度（token，用户可调），budgetWarnRatio 是它的百分比——两者缺一不可，否则"越过 80%"没有分母。
  • 并发（spawn_subagents）：子会话本地累计，结束后 settleFromSubSession 一次性归集到根。

5.7领域事件

事件谁发出什么时候谁关心
ToolDefinitionUpdatedEventToolDefinition元数据或 schema 更新成功运行中会话不订阅（快照已冻结）；新建会话会用新定义
BudgetWarningBudgetrecordUsage 首次越过 budgetWarnRatio（warned 置真）内循环 → ask_user 询问是否继续

插件不新增领域事件：安装 / 授权 / 停用是用户操作，改的是 PluginManifest 的授权意图，界面自己刷新即可（与"事件只通知"一致）。

本模块订阅 PolicyAdjusted（感知）：刷新备用模型链与信任清单的读取缓存（若有）。工具调用失败、模型调用失败都不是领域事件，它们是同步结果。

5.8聚合生命周期与规则

5.8.1 ToolDefinition

诞生变更终结重建
平台初始化（13 个内置工具播种：5 个编排 + 8 个本地能力）/ 用户注册外部工具 元数据或 schema 更新、activate / deprecate DEPRECATED（不再进入新会话快照） 应用启动时载入

规则（8 条）

  1. 工具严格串行执行，不存在并发工具调用。
  2. 一次模型响应里出现多个工具调用时，逐个执行、各自独立成败（可部分成功）。
  3. 工具失败不是领域状态：超时 / 异常 / 无返回都作为"一种工具结果"回灌模型，ReAct 继续。
  4. 超时由工具自带（timeoutMillis）；ask_user 可无限期等待。
  5. 执行前放行审批：sideEffect ≠ READ_ONLY 且不在 trustedToolIds 中 ⇒ 先 ask_user 放行；信任清单可覆盖不可逆工具。 插件来源的工具：source.type = PLUGIN 且其 PluginManifest.trusted = true ⇒ 视为已放行（安装时的一次同意 = 一次针对整包的放行审批）。 本地写入例外：edit_file / write_file / delete_file 首次问一次"允许本会话在此工作区内写入与删除文件？"，同意后该会话不再逐次问——这份信任记在运行期（按会话隔离、进程退出即失效，不落盘、不进 RuntimePolicy）：持久信任一条写权限是用户自己该做的决定，不该由一次点击替他做。
    本地命令工具例外：run_command 不走这条，改由规则 10 的绊线判定。
  6. 结果截断：超过 toolResultTruncateLength ⇒ 截断进上下文，完整内容落本地归档文件，ToolExecOutcome.resourceUri 指向它；会话销毁时一并删除。
  7. 重试语义：失败重试时，已成功的工具调用按"重放"处理，副作用风险由用户承担。
  8. 入参必须通过 inputSchema 的完整 JSON Schema 校验（draft-07，networknt json-schema-validator，见《模块-行动》§7.1 规则 8）；失败即返回错误结果（不执行，回灌模型自修复）。校验产出的是"违反项清单"而不是异常——校验失败是预期内结果，不是 bug。
  9. 本地能力只在一个根里动手：工作区根 = 进程启动时的工作目录（启动时求一次 toRealPath()；不做配置项——"我在哪个目录启动它，它就在哪儿干活"）。所有本地工具的路径都必须落在根内：相对路径拼到根下，绝对路径也接受但必须仍在根内；判定必须基于 real path（否则一个符号链接就能逃逸）；目标不存在时对父目录判定。越界不是异常，是普通工具错误结果（规则 3）。写/改文件先写 *.tmp 再原子改名；run_command 的 cwd 默认根、且只能是根内子目录；delete_file 不许删根本身。
    硬限制（超限一律走规则 6 截断 + 归档）：read_file 默认 2000 行，含 NUL 字节判为二进制并拒绝；list_dir 深度默认 2、最多 500 项，忽略 .git/target/node_modules/.idea；grep 最多 200 条、每条 ≤ 200 字符；fetch_url 只 http/https、默认 8000 字符、失败当普通结果；run_command 超时默认 120s、上限 600s、只回尾部 200 行 + 退出码、超时杀进程树；edit_file 的 oldText 必须恰好出现一次（0 次或多次都失败，并回报位置）；write_file 已存在且未 overwrite 即失败。
  10. run_command 默认放行，命中毒性特征才审批（这是对 I3 的实质让渡，见《模块-行动》§7.1 规则 10）：判定不靠正则，靠浅结构解析——引号消解后把命令行切成命令段，每段得到 程序 / 参数集合 / 操作数 / 重定向，段间保留 ; && || | 的拓扑；sh -c / eval 的实参文本再解析一遍（深度上限 2）。
    命中即审批，不是拒绝；解析失败、或嵌套超深 ⇒ 一律审批（fail-closed：看不懂就问）。审批文案带命中的规则名与原始命令。
    判定项：整盘或家目录的递归删除；mkfs / dd of=/dev/* / shred / 写 /dev/sd*；chmod -R 作用于系统目录或家目录（任一权限模式都算，不只看 777）；sudo / su / doas；管道末端是 shell 且上游是 curl/wget/base64 -d/eval；git push --force / git reset --hard / git clean -x；find -delete / find -exec / xargs + 删除类命令；fork 炸弹 / kill -9 -1 / shutdown / reboot；drop database / drop table / truncate table；把 .env、.ssh/id_*、.aws/credentials 读出或 POST 出去。
    它是绊线不是闸门：拦不住动态拼接（$(...)/$VAR/别名）、间接执行（xargs/find -exec）、以及项目自己的脚本（npm run build、mvn clean）——这几类恰好是最常见的真实事故，模型必须知道它没被保护。
    同理："信任工作区"只管 edit_file/write_file/delete_file，管不住 run_command 里的重定向与子进程（能跑 shell 就能写文件）。

5.8.5 Budget

诞生变更终结重建
会话开启（仅根会话创建，与 Session 同时刻）每次模型调用后累计；越过阈值置 warned会话销毁时物理删除会话续跑时载入

规则（5 条）

  1. 一个会话族一个台账，以根 sessionId 标识。
  2. 不预留、不分配额度。
  3. 只预警不中断。
  4. 只报一次。
  5. 子会话不自建 Budget，并发消耗先本地累计、结束后归集。

5.8.6 PluginManifest

诞生变更终结重建
安装（用户放 jar + 应用读 plugin.json；不存在则按默认创建：trusted=false、grantedCapabilities=∅） grant(端口名) / revoke(端口名)（按能力逐项勾选）；trusted 只在安装时确定 卸载：删除 plugins/<id>/ 目录（与"删 skills/ 目录即淘汰"同构）；应用内不提供删除 应用启动时载入（PluginRepository.list()）

规则（8 条）

  1. 落盘只存用户意图：id / version / apiVersion / trusted / grantedAt / toolIds / declaredCapabilities / grantedCapabilities。"已加载 / 加载失败"是进程内事实，不落盘（同一条理由：没人负责擦除的持久状态必然变脏）。
  2. 目录名 = Plugin-Id：不一致 ⇒ 拒绝安装（否则同 id 两个目录，卸载会漏）。
  3. grantedCapabilities ⊆ declaredCapabilities：勾选不能超出插件自报的可替换面。
  4. 同一端口至多一个启用者：冲突在启用时判定（安装不判），第二次启用被拒绝并提示冲突方；不做"后装覆盖"、不做优先级链。
  5. apiVersion 不符 / 重复打包宿主已提供的依赖 ⇒ 拒绝安装或启用，不允许"跑起来试试"。
  6. 工具清单不动：插件带来的工具就是 source.type = PLUGIN 的 ToolDefinition，status 始终 ACTIVE；停用插件时它们从目录里消失（不改 ToolStatus）。
  7. 升级 = 换 jar：同一 Plugin-Id 重新加载会与旧 ClassLoader 撞车，要求重启进程。
  8. 卸载不牵连历史：不删该插件产出过的 artifact（那些属于会话历史，随会话销毁清理）。
  9. 能力名与"声明"的来源：能力名 = 端口短名（Clock / TokenCounter / ModelInvocationPort / ExternalToolPort / HumanInteractionPort / ProgressPort / SessionRunner）+ 特殊能力 tools；declaredCapabilities 不靠插件自报，由装配层逐个探"该插件是否真的实现了它"，jar 内有工具声明即自动含 tools。

5.9.2 模型调用的两层校验（规则）

ModelInvoker 的完整时序见 第 9 章 9.11；「模型不可用 / 请求超限」的处理结果见 第 8 章 8.10。这里只保留跨层必须对齐的口径。

层位置口径失败后果
业务侧预算应用层 ContextWindowServicemin(策略阈值, maxInputTokens − inputSafetyMargin)事前折叠，不报错
调用侧硬校验基础设施 ModelInvokerestimatedPromptTokens vs 实际要用的模型 的 maxInputTokens（不含输出：输出有自己的上限）抛「请求超限」，由用例补折一次后重试
  1. 用量随请求下行：estimatedPromptTokens 由调用方填入 ModelInvocationRequest；执行器不得回查 Session（Session 不知道 contextLimit，回查还会破坏单向依赖）。
  2. 记账在调用方：ModelInvoker 只返回 usage，由调用方交给 BudgetService —— 否则会出现"基础设施 → 应用层"的反向依赖。
  3. 模型私有状态按产者隔离：reasoning_content（DeepSeek）/ 签名 thinking（Anthropic）/ thoughtSignature（Gemini）都是模型私有状态，不能跨模型搬运。解析侧收进 ModelInvocationResult.reasoning；调用方把 reasoning 与 producerModelId 一起落流水；组装侧只有目标模型 == 产者时才发出该字段，否则丢弃。能力标记不参与判定（缺省为空，按能力过滤会把主路径打坏）。
  4. 一个响应 = 一条 assistant 消息：content 与全部 tool_calls 不得拆成多条 assistant 消息。协议适配器只做“canonical ChatMessage → 目标线格式”的一次翻译；拆分/合并、连续同角色消息、tool_result 归到哪个 turn 全由适配器负责。应用层不得为了适配某个厂商而改变消息形态。
  5. 协议适配器接缝：ChatProtocolAdapter（buildRequest / parseResponse / 流式累加器 / 端点与请求头）由 Provider.protocol 选择；ModelInvoker 只管选模型、硬校验、重试与降级，不写死任何协议的字段名。已实现 OPENAI_CHAT / ANTHROPIC_MESSAGES / GEMINI；新增协议 = 新增一个适配器实现，不改上面的规则。
  6. 系统提示词独立于消息列表：systemPrompt 由调用方（ReActLoop / ContextWindowService / SessionTitleGenerator）从窗口推导后填入，不进 messages；工具清单同理：tools 取自 SystemPromptSnapshot.toolList（会话开启时冻结），执行器不得现查目录；落到各家协议里的差异（OpenAI 用首条 role=system、Anthropic 用顶层 system、Gemini 用 systemInstruction）由基础设施适配器吸收（见《模块-基础设施层》§10）。
  7. 端口失败用上下文错误码表达：ModelInvoker 失败时抛 ModelInvocationException(ModelError)，错误码取 M_*；调用方据此区分"不可用"（不改状态）与"请求超限"（补折一次）。
  8. 降级后由调用方切换会话模型：ModelInvocationResult.servedModelId 指出实际服务的模型；与请求的目标模型不同 ⇒ 调用方调 Session.switchModel(...) 让聚合 raise ModelSwitched（ModelInvoker 不碰聚合）。

情形语义唯一出处
