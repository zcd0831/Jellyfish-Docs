第 5 章

行动模块

行动模块回答三个问题：能做什么（工具）→ 用什么做（模型 / 供应商）→ 谁在做、花多少钱（代理 / 预算）。 它是唯一有权对外部世界产生副作用的模块（调工具、调模型、扣 token），也是唯一持有凭据的模块。

聚合 5 领域服务 3 端口 1 实现 · 1 声明 领域事件 2

5.1模块定位与边界

方向内容
本模块聚合ToolDefinition、Provider、Model、AgentDefinition、Budget
本模块对象所在的层领域层：5 个聚合及其规则；应用层：ToolExecutor、BudgetService；基础设施层：ModelInvoker、SkillSopProvider
被本模块引用的外部 ID（仅 ID）SessionId（感知，Budget.sessionFamilyRootId、子会话创建）、SkillId（记忆，仅作为绑定 ID）
被外部引用的本模块对象RuntimePolicy 的读取者（感知持有）、ToolId / ModelId / AgentId 被各模块引用
依赖纪律

本模块不自行实现任何端口。ModelInvocationPort 由基础设施 ModelInvoker 实现； load_skill 的 SOP 读取由基础设施 SkillSopProvider 实现；其余四个内置工具的处理器本来就在应用层。 行动模块因此对"文件、网络、终端"零依赖。

5.4聚合清单

聚合简介不变量
ToolDefinition 一个可被模型调用的动作定义：schema、来源、副作用等级、自带超时 ① 入参必须能通过 inputSchema 校验；② INTERNAL 工具只能指向内部处理器；③ 元数据 / 状态变更后 raise ToolDefinitionUpdatedEvent（运行中会话不订阅，因快照已冻结）
Provider 模型供应商：端点与凭据的唯一持有者 ① 凭据只存在于 Provider；② 一个 Provider 可对应多个 Model
Model 可调用的具体模型：上下文上限、能力标签、状态 ① status = ACTIVE 才能被调用；② 能力标签用于 spawn_subagents 时的模型匹配；③ 不承载价格（金额概念已删除）
AgentDefinition 代理身份与能力边界：基础 prompt + 绑定工具 + 绑定技能 ① 内置代理的 prompt 不可编辑；② 业务代理的工具 / 技能全部由用户绑定，不强制；③ 会话内 Agent 不可切换
Budget 会话族的 token 台账与一次性预警标记 ① 一个会话族一个 Budget，以根 sessionId 标识；② 只累加、不预留、不分配额度、不中断；③ warned 一旦置真不再预警

5.4.1 ToolDefinition

模型可以调用的一个动作；source 决定谁来执行。AgentDefinition.toolIds 决定"本代理能用哪些"；RuntimePolicy.trustedToolIds 决定"哪些免审批"。

内置工具入参出参领域后果处理器归属
generate_plan计划草案（steps + 每步声明的验证类型）"计划已创建"或失败原因PlanFactory 创建 Plan，raise PlanCreated规划
submit_stepsummary（必填）、artifacts?"已登记"内循环据此置 submitted，交外循环验收规划（由内循环识别）
ask_user问题文本用户回答阻塞同一 ReAct 循环；记 TOOL_REQUEST + TOOL_RESULT行动
spawn_subagentsList<SubagentRequest{agentId, modelId, task}>List<SubagentResult{sessionId, conclusion}>并行创建子会话、join-all、各子独立超时应用（SubagentLauncher，内部调 StartSessionUseCase）
load_skillskillNameSOP 全文注入一条 role=SYSTEM 的 Record基础设施（SkillSopProvider）

5.4.2 Provider / Model

  • 凭据只在 Provider；Model 通过 providerId 关联。
  • capabilities 的唯一消费者是 LLM：spawn_subagents 指定子代理模型时，按能力匹配（如需要 vision / function calling）。
  • 模型故障 → ModelInvoker 按 RuntimePolicy.modelFallbackChain 自动降级，并让 Session.switchModel() raise ModelSwitched。

5.4.3 AgentDefinition

  • source = BUILT_IN：反思 / LLM 裁判 / 经验检索 / 经验归纳，prompt 不可编辑、工具集写死。
  • source = USER_DEFINED：prompt 可改，工具与技能由用户自行绑定（不强制任何内置工具）。
  • 状态动词统一：submit / activate / deprecate。

5.4.4 Budget

  • 单位 token，不换算金额。
  • 只预警、不中断：达到 budgetWarnRatio → 外循环经 ask_user 询问是否继续；同一会话族只报一次。
  • 并发（spawn_subagents）：子会话本地累计，结束后 settleFromSubSession 一次性归集到根。

5.5领域服务清单

服务层简介依赖
ToolExecutor 应用 工具执行的唯一入口：合法性校验 → 放行审批 → 按来源分发（内部工具处理器 / ExternalToolPort）→ 结果截断归档 ToolDefinition、AgentDefinition、RuntimePolicy、ExternalToolPort、SkillSopProvider、ArtifactStore
BudgetService 应用 记账与预警：把会话族内任意位置的消耗归集到根 Budget，判定是否越阈值并触发预警 Budget、RuntimePolicy、Session（解析根）
ModelInvoker 基础设施 模型调用的唯一出口，实现 ModelInvocationPort：选模型 → 硬校验 → 取凭据调用 → 失败按备用链降级；只返回 usage，不记账 Model、Provider、PolicyRepository

5.8聚合生命周期与规则

5.8.1 ToolDefinition

诞生变更终结重建
平台初始化（5 个内置工具播种）/ 用户注册外部工具 元数据或 schema 更新、activate / deprecate DEPRECATED（不再进入新会话快照） 应用启动时载入

规则（8 条）

  1. 工具严格串行执行，不存在并发工具调用。
  2. 一次模型响应里出现多个工具调用时，逐个执行、各自独立成败（可部分成功）。
  3. 工具失败不是领域状态：超时 / 异常 / 无返回都作为"一种工具结果"回灌模型，ReAct 继续。
  4. 超时由工具自带（timeoutMillis）；ask_user 可无限期等待。
  5. 执行前放行审批：sideEffect ≠ READ_ONLY 且不在 trustedToolIds 中 ⇒ 先 ask_user 放行；信任清单可覆盖不可逆工具。
  6. 结果截断：超过 toolResultTruncateLength ⇒ 截断进上下文，完整内容落本地归档文件，ToolExecOutcome.resourceUri 指向它；会话销毁时一并删除。
  7. 重试语义：失败重试时，已成功的工具调用按"重放"处理，副作用风险由用户承担。
  8. 入参必须通过 inputSchema 校验，失败即返回错误结果（不执行）。

5.8.2 Provider

诞生变更终结重建
平台初始化 / 用户新增凭据轮换（updateCredential）、activate / deprecateDEPRECATED应用启动时载入

规则

  1. 凭据只由 Provider 持有，聚合里只存引用。
  2. 一个 Provider 对应多个 Model。
  3. Provider 弃用后其下 Model 不得被选中，除非已 ACTIVE 且明确在备用链中。

5.8.3 Model

诞生变更终结重建
随 Provider 注册activate / deprecate、能力标签更新DEPRECATED应用启动时载入

规则（5 条）

  1. 只有 ACTIVE 可调用。
  2. contextLimit 在调用前做硬校验（超限抛「请求超限」，不在此处折叠、也不降级，由外循环补折后重试）。
  3. 模型故障 → 按备用链降级并 Session.switchModel()。
  4. 无价格概念。
  5. 备用链全部失败不是状态迁移，聚合保持原状（见 5.9.3 与 第 8 章 8.10）。

5.8.4 AgentDefinition

诞生变更终结重建
平台初始化（内置 4 个代理）/ 用户创建绑定 / 解绑工具与技能、改 prompt、submit / activate / deprecateDEPRECATED应用启动时载入

规则（4 条）

  1. 内置代理 prompt 不可编辑、工具集写死。
  2. 业务代理工具不强制。
  3. 会话开启时冻结"绑定结果的内容快照"（由感知完成），之后改绑定不影响进行中的会话。
  4. load_skill 注入的 SOP 中若引用未绑定工具，属提示词一致性问题（感知组装时告警，不阻断）。

5.8.5 Budget

诞生变更终结重建
会话开启（仅根会话创建，与 Session 同时刻）每次模型调用后累计；越过阈值置 warned会话销毁时物理删除会话续跑时载入

规则（5 条）

  1. 一个会话族一个台账，以根 sessionId 标识。
  2. 不预留、不分配额度。
  3. 只预警不中断。
  4. 只报一次。
  5. 子会话不自建 Budget，并发消耗先本地累计、结束后归集。

5.9.2 模型调用的两层校验（规则）

ModelInvoker 的完整时序见 第 9 章 9.11；「模型不可用 / 请求超限」的处理结果见 第 8 章 8.10。这里只保留跨层必须对齐的口径。

层位置口径失败后果
业务侧预算应用层 ContextWindowServicemin(策略阈值, maxInputTokens − inputSafetyMargin)事前折叠，不报错
调用侧硬校验基础设施 ModelInvokerestimatedPromptTokens vs 实际要用的模型 的 maxInputTokens（不含输出：输出有自己的上限）抛「请求超限」，由用例补折一次后重试
  1. 用量随请求下行：estimatedPromptTokens 由调用方填入 ModelInvocationRequest；执行器不得回查 Session（Session 不知道 contextLimit，回查还会破坏单向依赖）。
  2. 记账在调用方：ModelInvoker 只返回 usage，由调用方交给 BudgetService —— 否则会出现"基础设施 → 应用层"的反向依赖。

5.9.3 模型不可用与请求超限（口径在此，处理在应用层）

情形语义唯一出处
模型不可用环境故障：不是业务失败，也不是状态迁移第 8 章 8.10
请求超限业务预算问题：强制折叠一次后重试第 8 章 8.10

本模块只负责 Model 聚合的规则（ACTIVE 才可调用、contextLimit 独立上限、能力标签）；降级实现见 第 9 章 9.11，失败后的状态落点见第 8 章 8.10。

    B->>B: consumedTokens += tokens
    B->>RP: budgetWarnRatio
    alt 首次越过阈值且 warned = false
        B->>B: warned = true
        B-->>BS: raise BudgetWarning
        BS-->>CALLER: 预警（由内循环经 ask_user 询问用户）
    end

要点：子会话并发时先各自累计，结束后 settleFromSubSession 一次性归集到根，避免并发写同一 Budget 聚合。

会话续跑程序重启后 resume：加载 Session / Plan / Budget；半截工具调用视为失败

步骤固化 / 判败 / 中断step 的三种结束：SUCCEEDED / FAILED / INTERRUPTED
步骤重试失败后新建 Attempt；达阈值则产生 Reflection
