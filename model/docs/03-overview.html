图 3-3　单向依赖：感知是叶子，谁都依赖它，它不依赖任何人

维持这张无环图的三个纪律
  1. 需要别人的内容 → 让调用方取好，用值对象传进来。 例：ContextWindowPolicy、AgentSnapshotInput、DistillationInput、RetrievalInput、FeedbackInput、ModelInvocationRequest。
  2. 需要别人的动作 → 走端口。 例：ModelInvocationPort（感知声明 / 行动实现）、InternalToolHandler（行动声明 / 规划+记忆实现）、SubagentRunnerPort（记忆声明 / 行动实现）。
  3. 只读别人的聚合不算依赖。 例：记忆按 RecordRange 只读 Session.Record；但绝不追写。

3.6十二个聚合与它们的红线

聚合是"必须一起改对"的一小组对象。每个聚合只有一根"根"，外面改它必须通过根。 最后一列是不变量——违反它的操作一律不允许。所有不变量都不依赖 RuntimePolicy： 配置只改变"外循环选择哪条路",不改变"什么状态是合法的"。

聚合模块一句话不变量（红线）
Session感知会话上下文事实流① 记录只追加，被引用的区间永不删改；② 快照创建即冻结；③ Agent 不可切换；④ 父取消级联子；⑤ 状态仅 RUNNING/RESUMABLE/ARCHIVED
RuntimePolicy感知运行环境策略单例① 全局唯一；② 不进会话快照；③ 只有用户可改
ToolDefinition行动一个可调用的动作定义① 入参须过 inputSchema；② INTERNAL 必须指向已注册处理器
Provider行动供应商与凭据持有者① 凭据只存于此；② 一 Provider 多 Model
Model行动具体模型与能力① 仅 ACTIVE 可调用；② 无价格概念
AgentDefinition行动代理身份与能力边界① 内置代理 prompt 不可改；② 会话内 Agent 不可切换
Budget行动会话族 token 台账① 一族一账；② 只累加，不预留不分配；③ warned 只置真一次
Plan规划一次工作分解① steps 非空；② 同时至多一个 RUNNING 步骤；③ SUCCEEDED 不可变；④ 重划只替换未执行尾部；⑤ 单写者，无需乐观锁
VerificationReport规划一次判定的结论① 不可变；② 三态；③ 只留失败层与失败原因
Experience记忆一条经验① 置信度 [0,1]；② 不绑定任何维度；③ ARCHIVED 不参与检索；④ 不超容量
Reflection记忆一次反思结论① 不可变；② 唯一归属 (planId, stepId, attemptNo)
SkillDefinition记忆程序性知识（SOP）① 仅 ACTIVE 进快照；② 不含工具依赖；③ SOP 不引用未绑定工具

3.7驱动：外循环就是 do-while

OuterLoopService.run(session):
    loop:
        ContextWindowService.ensureWithinLimit(session)       // 阻塞；算窗口、必要时折叠
        step = session.hasExecutablePlan() ? plan.getCurrentStep() : null
        iter = InnerLoopService.runIteration(session, step)    // 内循环只在"模型不再调工具"时返回

        if !iter.isConverged:                                  // 撞 maxReActRounds
            plan.markAttemptFailed(step, iter.attemptNo)
            advanceAfterFailure(step)                          // 重试 / 反思 / 重划
            continue                                           // 不需要用户介入，继续下一轮

        if step == null: return                                // 无计划且收敛：本轮交互完成
        if !iter.submitted: return                             // 模型在等用户：本轮结束，Attempt 挂起

        // 已提交
        if step.requiredVerifications.isEmpty():
            plan.markStepSucceeded(step, iter.submittedSummary, null)   // 不验证即完成
        else:
            report = VerificationService.verify(step, iter.attempt)
            advance(step, report)                              // 通过 → 推进；失败 → 重试/反思/重划

四条伴随规则：

  • 工具只有一类：generate_plan、submit_step、ask_user、spawn_subagents、load_skill 都是普通内置工具，靠"返回结果"改变领域状态；
  • generate_plan 成功后不打断内循环，模型确认后自然收敛，下一轮迭代转入计划执行；
  • 计划 COMPLETED 后会再跑一轮自由内循环，由模型产出最终答复（结论交付）；
  • 三条出口：未收敛（撞轮次上限）⇒ 判失败后继续；无计划且收敛 ⇒ 结束；有计划、收敛但未提交 ⇒ 挂起（Attempt 不落终态，等用户输入）；
    • \n
  • 经验检索的触发点是计划诞生 / 计划重划，不是每轮迭代。

3.7.1 一次尝试（Attempt）的边界

Attempt = 一个 step 的一次完整执行周期（可被多次用户输入切成多段 ReAct，但不切分 attempt）。

结束方式outcome消耗重试名额
submit_step → 验证通过SUCCEEDED—
验证失败 / 执行失败FAILED是
中断（Ctrl-C / 进程退出）INTERRUPTED否
收敛但未提交不结束，用户输入后续跑否

recordRange 始终连续（用户输入、注入、摘要都是 Record）； retryCount = FAILED 的次数；maxReActRounds 按"自上次用户输入以来的连续轮数"计。

条件结果
无计划 + 内循环收敛本轮交互结束，会话转为 RESUMABLE
内循环里 generate_plan 成功本轮收敛后，下一轮迭代发现"有计划了",转入计划执行
计划 COMPLETED再跑一轮自由内循环，由模型产出最终答复（结论交付）
计划 FAILED（外循环判定重划用尽）循环收敛退出，触发经验沉淀
模型不可用run() 立即返回；不改状态、不耗重试、不触发反思/重划；仅提示
请求超限强制折叠一次后重试；不耗重试；仍超限按模型不可用处理

3.10事件全景

领域事件由聚合根在状态真的改变后发出，代表"这件事已经发生了"。 应用层在事务提交后才发布，订阅方只看 ID 和事件内容。

事件谁发出什么时候谁关心
PlanCreatedPlan计划校验通过并创建记忆·经验检索
PlanCompletedPlan所有步骤成功记忆·经验沉淀
PlanFailedPlan外循环判定重划用尽并终止记忆（失败也沉淀）、界面
StepFailedPlan标记步骤失败规划·外循环
VerificationRejectedVerificationReport结论为不通过 / 无法判定规划·外循环
ReflectionRecordedReflection反思结论落库规划（回注）、记忆（素材）
ExperienceCreatedExperience归纳产出新经验界面
ExperienceReinforcedExperience加分成功 / 合并去重界面
ExperiencePenalizedExperience减分成功界面
BudgetWarningBudget首次越过预警阈值内循环 → 问用户
SummarizationCompletedSession摘要记录已追加界面 / 审计
SessionCancelledSession用户取消会话级联取消子会话
ModelSwitchedSession降级命中备用链审计 / 界面
PolicyAdjustedRuntimePolicy用户修改策略成功三个模块刷新读取缓存
ToolDefinitionUpdatedEventToolDefinition元数据或 schema 更新运行中会话不订阅（快照已冻结）

应用事件（不进领域模型）：SummarizationStarted（压缩开始，无状态转换）、ExperienceDistillationFinished（沉淀流程跑完）。
