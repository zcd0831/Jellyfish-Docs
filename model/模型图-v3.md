# Jellyfish Agent 领域模型 v3

## 一、驱动模型：外循环就是 do-while

```
OuterLoopService.run(session):
    do:
        ContextWindowService.ensureWithinLimit(session)        // 阻塞：计量、必要时压缩
        step = session.hasExecutablePlan() ? plan.getCurrentStep() : null
        iter = InnerLoopService.runIteration(session, step)     // 唯一出口：模型不再调工具

        if iter.submitted && step != null:                      // 模型调了 submit_step
            if step.requiredVerifications.isEmpty():
                plan.markStepSucceeded(step, iter.submittedSummary, null)
            else:
                report = VerificationService.verify(step, iter.attempt)
                advance(step, report)                          // 成功推进 / 失败→重试→反思→Replan
        // 未提交：attempt 不结束，step 保持 RUNNING，等用户下一次输入续跑
    while ( !iter.isConverged() || session.hasExecutablePlan() )
```

关键点：

1. **工具只有一类**：`generate_plan`、`submit_step`、`ask_user`、`spawn_subagents`、`load_skill` 都是普通 `INTERNAL` 工具，靠"返回结果"改变领域状态，**不需要任何控制流特殊处理**。
2. **`generate_plan` 成功后不打断内循环**：工具返回"计划已创建"，模型确认后自然收敛；下一次 do-while 迭代因 `hasExecutablePlan()` 为真而转入计划执行。
3. **经验检索的触发点是"Plan 诞生"**：首次生成时一次、每次 Replan 后一次，为每个 step 分配 `assignedExperienceIds`；无 Plan 的自由 ReAct 不检索经验。
4. **计划完成后的那一轮自由内循环就是"结论交付"**：模型看到各 step 的 `finalOutput`，产出最终答复。

## 二、`Attempt` 的语义

**`Attempt` = 一个 step 的一次完整执行周期**（可能被多次用户输入切成多段 ReAct 循环），边界只有三个：

| 结束方式 | outcome | 消耗重试名额 |
|---|---|---|
| `submit_step` 提交 → 验证通过 | `SUCCEEDED` | — |
| 验证失败 / 执行失败 | `FAILED` | ✅ |
| 中断（Ctrl-C / 进程退出） | `INTERRUPTED` | ❌ |

- **收敛但未提交不算边界**：attempt 继续，用户下一句话只是追加 `USER` Record 后继续跑；
- 因此 `recordRange` 始终连续（用户输入、经验注入、摘要都是 `Record`），`retryCount` = `outcome = FAILED` 的 attempt 数；
- `maxReActRounds` 按「**自上次用户输入以来的连续轮数**」计，用户介入即重置。

## 三、`submit_step` 契约

- 入参**必带** `summary`（可选 `artifacts`），直接落 `PlanStep.finalOutput`；
- **提交 ≠ 完成**：完成判定权归 `VerificationService`；
- `requiredVerifications` 为空的 step：**不做任何验证**，提交即完成，**不产生验证报告**（`finalVerificationReportId` 为 null），不留"免验证"痕迹。

## 四、内置工具（`SourceType.INTERNAL`）

| 工具 | 作用 | 领域后果 |
|---|---|---|
| `generate_plan` | 生成计划 | `PlanFactory` 校验并创建 `Plan`，raise `PlanCreated` |
| `submit_step` | 声明当前 step 完成 | 触发验证链；`finalOutput` 落库 |
| `ask_user` | 阻塞式人机交互 | 记 `TOOL_REQUEST` + `TOOL_RESULT`（用户回答即为 TOOL_RESULT） |
| `spawn_subagents` | 并行发起多个子代理并 join-all | 每次内部并行开多个完整 `Session`，`childSessionIds` 落 `Attempt`，预算结束后一次性归集到根 |
| `load_skill` | 读取技能 SOP | SOP 全文注入为一条 `role = SYSTEM` 的 `Record`（此后不滑出窗口） |

绑定规则：**业务 Agent 的工具全部由用户自己绑**（不强制）；**内置 Agent（反思 / 裁判 / 检索 / 归纳）的工具集固定写死**。

## 五、上下文与压缩

- 上下文 = `SystemPromptSnapshot` 渲染的 `role=SYSTEM` 前缀 + `Record` 序列（经筛选）；
- **不滑出窗口**：系统提示词、技能 SOP 注入、工具注入（`role=SYSTEM`）。例外：三类合计占比超过 `systemRecordRatioLimit` 时**只保留系统提示词**；
- 触发：**token 阈值**（`summarizationTokenThreshold`）→ 生成一条 `SUMMARY` Record → 窗口滑至最近 `contextWindowRecordCount` 条；
- **压缩是阻塞的**；摘要由**当前会话模型**生成，计 token 到 `Budget`；
- 发给模型的"请生成摘要"提示词**不进 `Record`、用户不可见**；用户只看到压缩结果（`SUMMARY` 记录）与 `SummarizationStarted/Completed` 的表现。

## 六、验证链

串行责任链 × step 声明过滤：`DETERMINISTIC → ENV_FEEDBACK → LLM_JUDGE → HUMAN_APPROVAL`。

- 报告**只保留失败原因 + 失败层 + 三态结论**；
- `PASSED` → 固化；`FAILED` → 重试/反思/Replan；`UNDETERMINED` → 转人工；
- **两个审批位置**：执行前的"放行审批"（非只读工具且未命中 `trustedToolIds` 时由 `ask_user` 触发）与执行后的"结果验收"（`HUMAN_APPROVAL` 层）。人工层返回 `同意 / 不同意 + 必填原因`；不同意 = 带原因重试该 step；
- 工具本身失败**不是**领域状态，只是"一种工具结果"，回灌给模型，ReAct 继续。

## 七、经验闭环

| 环节 | 触发 | 规则 |
|---|---|---|
| 反思 | 失败重试次数 ≥ `reflectionThreshold` | 反思子代理（内置 Agent）产出 `Reflection`；结论同时用于回注重试与沉淀素材；`reflectionThreshold > maxRetries` ⇒ 永不反思 |
| 沉淀 | `PlanCompleted` / `PlanFailed` | **归纳子代理**，每 Plan 至多 `experiencePerPlan` 条；语义重复 ⇒ 合并且提置信度 |
| 检索 | Plan 诞生 / 每次 Replan | 整库交检索子代理做语义筛选，按 step 分配 Top-N |
| 应用判定 | step 结束时 | "被应用" = 检索子代理**标注建议**的那些；成功 ⇒ `reinforce`（仅被建议的），失败 ⇒ `penalize`（**全部注入的**） |
| 置信度 | — | `[0,1]`，初值 `0.5`，`±0.1`，`< 0.2` 淘汰；容量上限按"最早且最少被使用"淘汰 |

## 八、预算

- **单位 token**，不换算金额；
- **无额度分配、无预留、不中断**：全局总预算只是汇总口径；`Budget` 以**会话族根**为单位做台账；
- 达 `budgetWarnRatio`（默认 80%）时 raise `BudgetWarning` → 内循环通过 `ask_user` 问用户是否继续；**同一会话族只报一次**；
- 并发（`spawn_subagents`）时子会话本地累计，结束后一次性归集到根。

## 九、九个场景的可执行走查

**场景 1（简单对话）**
`SessionFactory.start()` → 创建 `Session` + `Budget`（家族根）、`SystemPromptAssembler` 冻结快照、`SessionTitleGenerator` 生成标题（计 token）→ 追加 `USER` → `OuterLoopService.run()`：无 Plan → `ContextWindowService` 检查 → `InnerLoopService.runIteration(session, null)` → 模型调工具 → `ToolExecutor` → `TOOL_REQUEST/TOOL_RESULT` → 模型收敛 → 无提交、无 Plan、`isConverged = true` ⇒ 退出，`Session` 转 `RESUMABLE`。

**场景 2（模型主动提问）**
同上，`ToolExecutor` 执行 `ask_user` → 阻塞 → 追加 `TOOL_REQUEST`（问题）与 `TOOL_RESULT`（回答）→ **同一 attempt / 同一 ReAct 循环继续** → 收敛。

**场景 3（生成并执行计划）**
`runIteration` 内调 `generate_plan` → `PlanFactory` 校验（不可解析 / 空 steps / 引用未绑定工具 / 循环依赖 / 规模超预算）→ 创建 `Plan` + raise `PlanCreated` → 工具返回"已创建" → 模型收敛 → 下一次迭代 `hasExecutablePlan()` 为真 → `ExperienceRetriever.retrieveAndAssign()` → `getCurrentStep()` → `runIteration(session, step)` → `submit_step` → `VerificationService.verify()` → `markStepSucceeded` → … → `PlanCompleted` → `ExperienceDistillationService.distill()` → 下一轮自由内循环由模型产出最终答复 → 退出。

**场景 4（执行中需要人工判断）**
- 若走 `ask_user`：同场景 2，阻塞在同一 attempt 内，回复后继续；
- 若模型直接输出一段提问并收敛（没调 `ask_user`）：`iter.submitted = false` ⇒ attempt **不结束**、step 保持 `RUNNING`、不消耗重试名额；用户下一句作为 `USER` Record 追加，**同一 attempt 继续跑**，直到 `submit_step`。

**场景 5（失败 n 次后成功 → 经验 → 下次一次成功）**
失败：`VerificationService` 回 `FAILED` → `markStepFailed` → `Attempt(FAILED)` → 未达阈值则直接回注失败原因重试；达阈值则反思子代理产出 `Reflection` 并回注 → 成功后 `SUCCEEDED` → `PlanCompleted` → 归纳子代理 → `Experience`（低初值置信度）→ raise `ExperienceCreated`。
下次同任务：`generate_plan` 成功后 `ExperienceRetriever` 分配给 step → 注入为 `SYSTEM` Record → step 成功 → `ExperienceFeedbackService.onStepSucceeded()` → 对"被建议的"经验 `reinforce`。

**场景 6（读技能 SOP）**
系统提示只有 `ACTIVE` 技能的 `name + description` → 模型调 `load_skill(skillName)` → `SkillDefinition.renderDetailedSop()` → 注入 `role=SYSTEM` 的 `Record`（不滑出窗口）→ 继续 ReAct。（`SystemPromptAssembler` 需校验：SOP 引用的工具必须在 `AgentDefinition.toolIds` 内。）

**场景 7（并行子代理）**
模型一次调 `spawn_subagents(List<SubagentRequest>)` → `ToolExecutor` 内部**并行**创建多个子 `Session`（`SessionFactory.startSubSession`，agent/model 由 LLM 指定并按 `capabilities` 匹配；子会话也是完整内外双循环）→ join-all → 每个子代理各有独立**执行超时**（从实际开始运行计时）→ 返回 `List<SubagentResult>`（各子代理独立成败，超时返回"超时未完成"）→ 主会话归纳。子会话再开子代理被禁止；中断时已完成的保留。

**场景 8（上下文压缩）**
`ContextWindowService.ensureWithinLimit()` 计量 token → 超 `summarizationTokenThreshold` → 应用事件 `SummarizationStarted`（用户可见"压缩中"）→ 用当前会话模型生成摘要（提示词**不进 Record**，计 token）→ `Session.markSummarized(summary)` 追加 `SUMMARY` Record 并滑窗 → raise `SummarizationCompleted` → 用户看到摘要记录 → 继续。

**场景 9（子代理 token 归集）**
每个子会话的每次 LLM 调用都经 `BudgetService.recordUsage(会话族根, tokens)`；为避免并发写，子会话本地累计、结束后一次性归集 → 用户看到的是**整个会话族**（主会话 + 全部子代理）的消耗。

## 十、领域事件的产生与订阅

| 事件 | raise by | 触发时机 | 订阅方 |
|---|---|---|---|
| `PlanCreated` | `Plan` | `PlanFactory` 校验通过并创建 | `ExperienceRetriever`（分配经验） |
| `PlanCompleted` | `Plan` | 全部 step 成功 | `ExperienceDistillationService` |
| `PlanFailed` | `Plan` | Replan 代次用尽 | `ExperienceDistillationService`（终局失败也沉淀）、界面 |
| `StepFailed` | `Plan` | `markStepFailed` | 外循环（retry / 反思 / Replan 决策） |
| `VerificationRejected` | `VerificationReport` | 结论为 `FAILED` / `UNDETERMINED` | 外循环 |
| `ReflectionRecorded` | `Reflection` | 反思结论落库 | 外循环（回注）、沉淀候选 |
| `ExperienceCreated` | `Experience` | 归纳产出 | 无 |
| `BudgetWarning` | `Budget` | `recordUsage` 首次越过阈值 | 内循环 → `ask_user` |
| `SummarizationCompleted` | `Session` | `markSummarized()` | 界面 / 审计 |
| `SessionCancelled` | `Session` | 用户取消 | 子会话级联取消 |
| `ModelSwitched` | `Session` | 降级策略命中 | 审计 / 界面 |
| `ToolDefinitionUpdatedEvent` | `ToolDefinition` | 元数据或 schema 更新 | **运行中会话不订阅**（内容快照已冻结） |

> 两个**应用事件**：`SummarizationStarted`（压缩过程开始，无聚合状态转换）、`ExperienceDistillationFinished`（沉淀流程跑完）。按"领域事件必须由聚合根 raise"的原则，它们不进领域事件集合。

## 十一、v2 → v3 变更清单

| 类型 | 变更 |
|---|---|
| 驱动 | 外循环改为 **do-while**（原 v2 缺 `SessionRunner`）；`InnerLoopService.runIteration(Session, PlanStep)` 第二参可空，返回 `IterationResult` |
| 新增概念 | `submit_step` 工具契约、`IterationResult`、`ToolExecutor`、`PlanFactory`、`ContextWindowService`、`SessionTitleGenerator`、`ExperienceRetriever`、`ExperienceDistillationService`、`ExperienceFeedbackService`、`PlanStep.assignedExperienceIds`、`RuntimePolicy.subagentExecutionTimeoutMillis` |
| 语义变更 | `Attempt` = 一个 step 的一次完整执行周期（用户输入不切分）；`maxReActRounds` 按"自上次用户输入以来的连续轮数"；无验证声明的 step 不产生 `VerificationReport`；`spawn_subagents`（复数、内部并行、join-all、各代理独立超时） |
| 修正 | `SummarizationStarted` 降为应用事件（`SummarizationCompleted` 由 `Session` raise）；`AgentSnapshotData` / `PricingPolicy` / `Context` 实体 / `SkillDefinition.toolIds` / `PlanStep.dependsOn` / `Experience.agentId` 等已在 v2 删除，v3 保持删除 |
| 保留但需注意 | "验证声明不强制"给了模型绕过验证的合法口子（属提示词/使用习惯问题，模型层不再约束） |
