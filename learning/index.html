一句话认识 Jellyfish

Jellyfish 是一个用 Java 1.8 编写的轻量级 AI Agent 工具：内核只负责跑 ReAct 循环、管会话、判权限、派发扩展点； 模型能用的全部能力（读写文件、跑命令、搜代码、连 MCP、压缩上下文、落盘会话）都由独立打包的 PF4J 插件提供， 插件与内核之间没有编译期依赖。同一套内核被 -cli、-tui、-server 三种外壳共享。

怎么用这套文档最高效

每页的「学习目标」先扫一眼，然后把对应的源码文件在编辑器里打开，照着页里的 文件:行号 跳。 页里的代码片段都是从真实源码摘的（含注释原文），但注释往往比代码更值钱——它们记录了当时权衡的理由， 这是文档没法凭空补出来的部分。

引用某一行：每个代码块都带行号，点击行号即可复制该行的链接 （形如 04-agent-loop.html#cb-3-L45）；也可以手写 #L45 简写， 表示「本页第一个代码块的第 45 行」。代码块右上角的 #cb-3 锚标用来引用整块。 把链接发给别人，对方打开后会自动滚到并高亮那一行。 （若某个代码块在 HTML 里显式写了 id，会优先用它作为锚点前缀，长期引用更稳定。）

离线阅读：样式表与代码高亮主题都已内联，断网也能正常阅读与复制。 代码高亮与图表渲染用 assets/vendor/ 下的两个第三方库 （highlight.min.js / mermaid.min.js，体积大、属第三方构建产物， 不在版本库里）：本地有文件就用本地，缺文件时自动回退 CDN； 两者都不可用时，图会以源码文本形式展示并在页首给出提示，不会变成空白。

关键结论

  1. Jellyfish 的架构可以一句话概括：内核保持最小 + 能力全在插件 + 三外壳共用一个装配。
  2. 所有设计的默认方向都是「更严」：权限 fail-closed、项目配置默认不信任、插件故障即拒绝、插件放行都表达不了。
  3. 它的代价同样明确：不装插件内核近乎空转、jar 变更必须重启进程、Java 8 锁死写法。
  4. 读它的正确方式不是「逐文件读完」，而是顺着一次工具调用走完全程——那条路径把所有核心模块都串起来了。
