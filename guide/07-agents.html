07 agents.json 与工具权限

上一页配好了「用哪个模型」，这一页配「谁来干、能干到什么程度」。agents.json 只有四个字段， 但其中 permissions 的三段工具名语义决定了一个 agent 能不能读文件、能不能写文件、哪些调用会被弹框—— 这是 Jellyfish 权限体系里最需要一次读懂的地方。本页同时讲清提示词文件 {agentId}.md、 内置的 default-agent.json，以及内核自带的子代理委派（task 工具 + subAgent 配置段）。

学习目标

  • 说清一个 agent 由哪三部分组成，以及系统默认 agent jellyfish 是从哪来的；
  • 写出 agents.json 的四个字段（description / permissions / delegatable / model）并知道各自的默认值；
  • 准确使用 allowedTools / deniedTools / askTools，说清「字段缺失」与「显式 []」的区别和三者优先级；
  • 在 -tui / -server / -cli 三种外壳下预判 askTools 里的工具会发生什么；
  • 给一个 agent 写提示词文件 {agentId}.md，并避开 agentId 的命名限制；
  • 用 task 工具把子任务委派给子代理，并读懂 subAgent 段 11 个字段（含哪几个键要重启才生效）；
  • 读懂屏幕上子代理的轨迹行与它花掉的 token 记在谁头上。

agent 是什么

在 Jellyfish 里，agent = 提示词 + 工具权限 + 可选的模型偏好。它不是一个进程、不是一个容器， 而是一组「这个角色是谁、能碰什么、愿意用哪个模型」的声明。内核在每次起回合时按当前会话绑的 agent 组装这三样东西： 提示词进 system prompt，权限进 PermissionManager 收口，模型偏好决定这次用哪个 provider / model。

为什么提示词不在 agents.json 里

系统提示词往往是多段长文（角色、工作方式、边界），塞进 JSON 字符串里既难写也难读。内核因此把它拆到 与配置文件同目录的 {agentId}.md：配置文件回答「有哪些 agent、各自什么权限」， Markdown 文件回答「它该怎么说话」。

Jellyfish/README.md:487-499（配置五份文件表，含 `agents.json` 与 `default-agent.json` 的定位）、Jellyfish/README.md:695-727（`agents.json` 示例与字段表）

agents.json 完整示例与字段表

这是仓库 README 里给出的完整示例，两个 agent 分别演示「只拒绝两个工具」与「只放行三个只读工具」两种姿态：

{
  "agents": {
    "coder": {
      "description": "通用编码助手",
      "permissions": {
        "deniedTools": ["write_file", "edit_file"],
        "askTools": ["shell"]
      }
    },
    "scout": {
      "description": "只读摸清相关代码，只回传结论",
      "delegatable": true,
      "model": "openai/gpt-4o-mini",
      "permissions": {
        "allowedTools": ["read_file", "list_dir", "grep_files"]
      }
    }
  }
}

配置：agents.json 顶层只有一个 agents 对象，键是 agentId，值是 agent 定义。

字段类型必填默认值含义示例
agents.<agentId>.description string 选填 null（不写就没有描述） agent 的一句话说明，供人阅读；不写不影响功能，只是 /agent 等展示处没有说明文字 "通用编码助手"
agents.<agentId>.permissions object 选填 {}（内置默认 agent 用的就是这个值，表示不设限） 工具权限三段，见下一节 { "deniedTools": ["write_file"] }
agents.<agentId>.delegatable boolean 选填 false 这个 agent 能不能被 task 工具当作委派目标。不配就不出现在模型看到的可用类型清单里 true
agents.<agentId>.model string 选填 null（不写就跟随全局默认） 这个 agent 的偏好模型，写法与 /model 参数一致（openai/gpt-4o-mini 或裸 gpt-4o-mini）。它的优先级低于「会话显式选定的模型」、高于全局默认：没显式选过模型的会话绑上它会落到这个模型上 "openai/gpt-4o-mini"

生效方式：/reload 生效——agents.json 是内容类配置，改完敲 /reload 会重读配置并重建 agent 索引，不必重启进程。

工具名是 shell，不是 bash

上面那段示例取自 Jellyfish/README.md:695-707。工具名以源码为准：官方 shell 插件注册的工具名是 shell（ShellTool.TOOL_NAME = "shell"，由 ShellPlugin 用它注册该工具）， Jellyfish-Plugins/README.md:53 的插件一览也写作 shell； Jellyfish-Plugins 的源码里不存在名为 bash 的工具（bash 只是它用 /bin/sh -c 执行命令这件事的俗称）。 内核文档早期版本在示例与审批框样张里误写成了 bash，现已改回 shell （Jellyfish/README.md:706 与 Jellyfish/README.md:281 两处）。如果你手上是旧版文档，照抄会写成一个 命中不了任何工具的名字——效果是「不限制任何工具」而不是「每次跑命令都要批准」，务必手改成 "askTools": ["shell"]。

工具权限三段：allowedTools / deniedTools / askTools

这是本页的重点。permissions 里可以写三个数组，每个数组的元素都是工具名 （就是 08 页总表里那一列：read_file、write_file、shell、 todo_write、task、mcp__<server>__<tool>……）。

配置

字段类型必填默认值含义示例
permissions.allowedTools array<string> 选填 字段缺失 = 不限制（不做白名单收口） 只放行这些工具。同时决定子代理能看到哪些工具（只随委派生效） ["read_file", "list_dir", "grep_files"]
permissions.deniedTools array<string> 选填 字段缺失 = 不限制 显式拒绝这些工具，优先级最高 ["write_file", "edit_file"]
permissions.askTools array<string> 选填 字段缺失 = 不限制（不弹审批） 这些工具每次调用都要人工审批；三种外壳行为不同 ["shell"]

语义：字段缺失 ≠ 显式空数组

三段工具名的语义是：字段缺失 = 不限制，显式写 [] = 该方向上一个都不放行 （allowedTools: [] 就是全拦）。也就是说，这两个写法表达的意思正好相反： 

{
  "agents": {
    "coder": {
      "description": "只显式拒绝两个工具，其余全不限制",
      "permissions": {
        "deniedTools": ["write_file", "edit_file"]
      }
    }
  }
}
想表达「只拒绝两个工具」就不要写 allowedTools: []

allowedTools: [] 是「全拦」而不是「不限制」。写成 { "allowedTools": [], "deniedTools": ["write_file", "edit_file"] } 的结果是 这个 agent 一个工具都用不了——它想要的「其余不限制」恰好被自己写成了反面。 要表达「只显式拒绝两个工具、其余不限制」，就直接省略 allowedTools 这个字段。

优先级：deniedTools > askTools > allowedTools

flowchart TD C["模型发起一次工具调用"] --> D{"工具名命中 deniedTools?"} D -->|"是"| X["直接拒绝"] D -->|"否"| K{"工具名命中 askTools?"} K -->|"是"| TUI["-tui：弹审批选择框"] K -->|"是"| SRV["-server：推进 SSE（approval_required）"] K -->|"是"| CLI["-cli：一律按拒绝处理"] K -->|"否"| A{"allowedTools 含它，或该字段缺失?"} A -->|"是"| OK["执行"] A -->|"否"| X2["拒绝（不在白名单里）"]

图 7-2　三段工具名的判定顺序：先拒、再问人、最后看白名单

外壳命中 askTools 时会发生什么
-tui 弹出审批选择框（↑/↓ 选，Enter 确认，Esc 拒绝并中断回合），批准才执行
-server 把待审批项推进 SSE 流（approval_required），由 POST /sessions/{id}/approvals/{requestId} 裁决
-cli 没有审批界面（也没有审批者），因此一律按拒绝处理——绝不静默放行

审批框等不到答复（缺省 120 秒，见 permission.approvalTimeoutSeconds）按拒绝处理； 把该键写成 0 则表示永不超时——「等不到人」不再收敛为拒绝，而是一直等下去。 审批超时的细节与 permission 段其它字段见 10 权限与审批。

allowedTools 还有一层作用：决定子代理能看到哪些工具

allowedTools 不只是一道白名单，它同时回答「这个 agent 被 task 委派时，子代理的工具清单是什么」。 只给它 ["read_file", "list_dir", "grep_files"]，子代理就既看不到也调不了写类工具。 这条作用只随委派生效，主会话不受影响。

生效方式：/reload 生效。

常见问题

  • 配了 askTools，在 -cli 里却直接失败了？那是设计：-cli 没有审批者，ASK 等于拒绝。想在无人值守下放行就把该工具从 askTools 拿掉（或按 10 页的说明改用别的口子）。
  • 把工具同时写进 allowedTools 和 askTools 会怎样？按优先级走：仍然每次弹审批——askTools 比 allowedTools 高。
  • 把工具同时写进 deniedTools 和 allowedTools 呢？拒绝生效，deniedTools 优先级最高。
  • 写了一个不存在的工具名？静默——不告警、也不报错，因此这个条目等于没写。三段工具名在源码里只是一组字符串：配置侧由 AgentPermissions 收下并归一，判定侧是 PermissionPolicy 的三个集合，命中就是精确相等（deniedTools.contains(toolName)）——全仓库没有任何一处把它与实际注册的工具名对照。内核在权限这件事上只有一条告警：会话引用了配置里查不到的 agentId（那条会明说「该会话的工具调用一律拒绝」）；子代理权限比父更宽是被直接拒绝而不是告警。所以写错工具名不会有任何提示，只能自己核对 08 页的工具名总表。

提示词文件 {agentId}.md

提示词文件 {agentId}.md

是什么
每个 agent（包括内置的系统 agent）的系统提示词来自与配置文件同目录的 {agentId}.md，内容就是它的系统提示词，可以是多段长文。
怎么用
在 agents.json 旁边放一个同名文件即可，不需要在任何配置里声明路径： 
~/.jellyfish/agents.json      ← 声明 agent 与权限
~/.jellyfish/coder.md         ← coder 的系统提示词
~/.jellyfish/scout.md         ← scout 的系统提示词
切过去用 /agent coder。{agentId}.md 是原文，不做模板插值—— 里面的 ${VAR} 不会被替换成环境变量。

配置

字段类型必填默认值含义示例
文件位置 路径 选填 与 agents.json 同目录 系统提示词的正文所在位置；不支持配置到别处 ~/.jellyfish/coder.md
文件名 = agentId string 必填 — 文件名必须与 agents.json 里的键一致 coder.md 对应 "coder"

命名限制：agentId 同时是文件名，因此不能含路径分隔符或 .. （含这类字符的条目会被整条丢弃并告警）。

文件不存在不阻断启动：只有 /agent 切过去时才提示「该 agent 没有系统提示词」。

完整示例——一份可以直接用的 coder.md：

# 角色

你是这个仓库的编码助手。改代码前先看清楚上下文，改完能说清自己动了什么、为什么。

# 工作方式

1. 动手前先用 `read_file` 读完要改的那个文件，必要时用 `grep_files` 找出所有调用点；
2. 只改必要的行，不要顺手重排无关代码、不要改无关文件的格式；
3. 改完跑一次相关单测，把命令与结果如实说一遍；
4. 遇到需要我拍板的事，用 `ask_user` 问，不要自己替我选。

# 边界

- 不要执行 `git push`、`git reset --hard` 这类会改动远端或丢历史的命令；
- 不要修改 `pom.xml` 里的版本号与依赖坐标；
- 不确定的地方直说不确定，不要猜一个看起来合理的答案。

常见问题

  • 改了 md 文件要重启吗？与 agents.json 同口径：敲 /reload。
  • 切过去只提示「没有系统提示词」？说明文件没放对位置（必须在 agents.json 同目录、文件名与 agentId 逐字一致），或文件名里带了多余后缀。
  • 能在 md 里写 ${VAR} 引用环境变量吗？不能，提示词是原文，不做插值。

default-agent.json：系统默认 agent

内置的系统默认 agent

是什么
内核随 jellyfish-infra 发布在 classpath 根的一份内置定义，配合同目录的 jellyfish.md 使用。它是用户改不了的：不走双源合并。
怎么用
不用做什么——每次启动、每个新建会话都绑这个内置 agent。想用自定义 agent 必须手动 /agent <agentId> 切换。

内置定义原文（default-agent.json）：

{
  "agentId": "jellyfish",
  "description": "系统默认 agent",
  "permissions": {}
}
同名 jellyfish 写不进用户配置

用户 agents.json 里写同名 jellyfish 会被忽略并告警 （内置定义不可被覆盖）。想用自己的提示词与权限，就取一个新名字（例如 coder）， 然后在会话里 /agent coder。

配置：这份文件不在双源（全局级 / 项目级）管辖之内，位置固定为 classpath 根。

常见问题

  • 为什么我配的权限没生效？先确认当前会话绑的是哪个 agent（/agent 查状态）：默认永远是内置的 jellyfish，它的 permissions 是空的。
  • 能改 default-agent.json 吗？不能，它是 classpath 里的内置资源。

是什么

子代理委派：task 工具

模型可以把一段自足的子任务委派给另一个 agent去做，只拿回它的最终结论。 这个能力内核自带（不是插件提供），由 agents.json 里标了 delegatable: true 的 agent 提供——不配 delegatable 的 agent 不会出现在模型看到的「可用委派类型」清单里。

task 工具（内核自带）

是什么
把一段自足的子任务交给一个子代理。task 只做三件事：把模型给的参数翻成一次委派、 把子代理的进度转给外壳、把结果渲染成回灌文本。所有准入判定与执行编排都在内核的 SubAgentLauncher 里——工具层不重复它们。
怎么用
你通常不用手敲它，模型会自己决定何时调用（系统提示里有一段「什么时候该委派」的选型文字）。 想手动验证就按下面的参数发一次调用。

配置——task 的参数来自 ToolDescriptor：

字段类型必填默认值含义示例
subagent_type string 必填 — 子代理类型，可取系统提示中列出的可委派类型之一（即 delegatable: true 的那些 agentId） "scout"
description string 选填 null（不写即缺省；此时开场行只写「开始」） 一句话说明这次委派要做什么，供人阅读与日志排查 "摸清鉴权链路"
prompt string 必填 — 给子代理的完整任务说明。它看不到本次对话，因此必须自足（背景、目标、验收标准都写进去） "读 src/auth 下所有文件，列出……"

subagent_type 缺失时工具不执行，直接回一条 「[子代理未开始] 缺少参数 subagent_type……」，并带上终态标记（界面会显示警示而不是「正常跑完」）。

完整示例——README 给出的纯配置写法（一个可被委派的 scout）：

{ "agents": { "scout": {
  "description": "只读摸清相关代码，只回传结论",
  "delegatable": true,
  "model": "openai/gpt-4o-mini",
  "permissions": { "allowedTools": ["read_file", "list_dir", "grep_files"] }
} } }

三条必须记住的隔离规则

  • 子代理与主会话除了那段任务之外相互隔离：它看不到本次对话的历史、不知道你读过哪些文件、也不知道主会话用的哪个模型，因此任务描述必须自足；
  • allowedTools 只随委派生效：只给它只读工具，它既看不到也调不了写类工具；
  • 子代理不继承主会话的模型：用自己的 model，没配则落到全局默认。想在探索上省钱就给它写个便宜模型。

屏幕上你能看到的：子代理在跑时工具轨迹出现 ⎿ task，下面缩进两格跟着它的每一步工具调用（ · read_file）；完成之后收成一行：

      ⎿ task · 子代理 scout · 3 轮 · 123456 tok · {"prompt": "…"}

轨迹行上的 123456 tok 是精确值不是缩写，因此能与 /usage 里的数字直接对上。 零用量与未跑起来的场景不写 token 数，未收敛时才额外补一句「结论不完整」。

token 记在谁头上：子代理花掉的 token计入父会话（/usage 看得到）， 但子代理的会话不留痕——不落盘、不进 /session 列表。

两道上限：递归有两道——subAgent.maxDepth（一条链多深）与 subAgent.maxSpawnsPerTurn（一个顶层回合里累计能派多少个，不是「一层扇出多少」， 派生一个少一个，与并发无关）。

回灌文本的首行就是结论，取值来自内核的状态机：

首行形态含义
[子代理 scout 已完成 · N 轮]正常收敛，后面跟着它的最终结论
[子代理 scout 未收敛 · N 轮]撞上轮数 / token / 墙钟之一，末尾会给出完整记录路径（可用 read_file 读）
[子代理 scout 已取消]回合被中止 / 取消
[子代理 scout 执行失败]子代理跑挂了
[子代理未开始]参数缺失或被拒绝，一次都没跑

常见问题

  • 模型从来不派子代理？检查目标 agent 有没有 delegatable: true；没有它不会出现在可用类型清单里。
  • 子代理说「不知道你在说什么」？任务描述不自足。它看不到对话历史，把背景、目标、验收标准都写进 prompt。
  • 子代理把项目改坏了？给它配 allowedTools 只读白名单，它调不到写类工具。
  • 子代理的会话在哪找？找不到——子代理的会话是临时的，不落盘、不进 /session；花掉的 token 记在父会话的 /usage 里。

subAgent 配置段全字段表

subAgent 是 jellyfish.json 里的一个段，管「能派多深、能派多少、跑多久、花多少 token、归档留多少」。 字段与缺省值如下（缺省值逐项照抄 README）：

字段类型必填默认值含义示例
enabled boolean 选填 true 全局开关。关掉后 task 工具直接不再注册，模型看不到它 false
maxDepth int 选填 1 允许的最大委派层数（主会话 → 子代理 → 孙代理），写 0 表示禁止委派 2
maxSpawnsPerTurn int 选填 12 单个顶层回合内允许派生的子代理总数（累计、派生一个少一个，不是并发数）。取 12 是为了让一次编排（步骤数以十几计）开箱可用 24
maxRounds int 选填 8 子代理自己那个回合的最大轮数，不跟随 react.maxRounds 12
maxConcurrentRuns int 选填 3 全局同时运行的子代理 run 数上限（不含父回合）。超出的 run 进等待区。run 跑在独立的 agent-run 线程池上，父回合等子 run 时会让出并发许可 4
maxQueuedRuns int 选填 64 等待区容量：并发满员时最多允许多少个 run 排队等许可。它不提高并行度，调大只把「当场失败」推迟到更晚的积压点；写 0 或负数按缺省值处理（不允许无界） 128
runTimeoutMillis long 选填 300000 单个 run 的墙钟上限（毫秒），从它真正开始执行起算（排队等许可的时间不算它跑的时间）。到点取消该 run 并记为「截断」，原因写进回灌文本首行 1200000
runTokenBudget long 选填 500000 单个 run 的累计 token 上限；写 0 表示不限制。它通常比树预算先撞上：预算是累计口径，「带着大材料又跑很多轮」的子代理会先触到它 200000
treeTokenBudget long 选填 6000000 一棵 run 树的累计 token 上限；写 0 表示不限制。缺省刻意等于 maxSpawnsPerTurn × runTokenBudget（12 × 50 万）。比这个乘积小，树预算会先于单 run 预算生效，表现成「某几个步骤失败了」。调大 maxSpawnsPerTurn 时要一起调大 12000000
archiveKeepFiles int 选填 200 run 归档目录（<toolOutput.dir>/subagent-runs）最多保留的文件数；写 0 表示不清理 500
archiveMaxBytes long 选填 104857600（100 MiB） run 归档目录最多占用的字节数；写 0 表示不清理 209715200

三组上限是正交的：maxDepth 挡「一条链多深」，maxSpawnsPerTurn 挡「一个顶层回合里累计派多少个」， maxConcurrentRuns 挡「全局同时在跑多少」；三个 token / 时间上限挡的是「跑飞了也停得下来」。 除 enabled 外，非法值一律回退缺省值。

这几个键什么时候读：哪些是「第一次提交 run 时定型」

这张表按源码逐个键核过（不再是「README 只点名了前几个」的状态）：只有执行资源那一档要重启， 其余都是现读现用。注意 README 把 maxDepth 与并发项并列写成「需重启」——那一句只对池上界成立。

字段何时读取改完怎么生效
maxConcurrentRuns / maxQueuedRuns 本次进程第一次提交 run 时建一次执行资源（并发许可数、agent-run 池上界、等待区容量），此后不再变——执行资源不能重建，重建就得动在途任务 需重启
maxDepth 被读两处：每个顶层回合开始时读一次写进该回合的委派作用域（深度判定用的是这一份，报错文案里的层数也来自它）；第一次提交 run 时另读一次，只为算池上界（maxConcurrentRuns × (maxDepth + 1)） 深度判定：/reload 生效（下一个顶层回合按新值）；池上界：需重启
maxSpawnsPerTurn / runTokenBudget / treeTokenBudget 每个顶层回合开始时读一次，写进该回合的委派作用域（本回合能派多少、单个 run 与整棵树的 token 上限都由这份作用域约束） /reload 生效（下一个顶层回合按新值）
runTimeoutMillis 每次起看门狗时读（每个 run 各一个定时器，因此不缓存） /reload 生效（下一个 run 就按新值计时）
maxRounds 每次派 run 时读：派子代理那一步把它作为子回合的轮数上限传下去 /reload 生效（下一次委派按新值）
archiveKeepFiles / archiveMaxBytes 每次归档一个 run 时读：收尾归档那一步现取这两个值，连同归档正文一起交给落盘存储做清理 /reload 生效
enabled 两处：重算注册状态时（启动期与 /reload 各一次，决定 task 工具与「可委派类型」清单注册与否）；另外每次组装系统提示贡献时再读一次，补上「配置刚改完、注册重算还在队列里」那段窗口 /reload 生效（关掉后 task 工具直接不再注册）
为什么「并发 / 等待区 / 池上界」要重启，而深度与预算不用

内核在配置装载（refresh()）之前就装配好了调度器，若在装配期读，读到的只会是缺省值； 而执行资源（许可数、线程池、等待区容量）一旦建好就不能重建——重建要动在途任务， 所以它推迟到第一次提交 run 时按当时的配置建一次，此后即使 /reload 也不变。 代价是这类失效没有任何提示：配置里明明写着 20 分钟，现场表现仍是一律按 300 秒掐。因此宁可让你重启一次， 也不让你以为改生效了。深度与预算不在这一档——它们每次现读现用（委派作用域每个顶层回合开一次）， 所以 /reload 后下一个回合就按新值生效。

「这一批派得比并发多」不等于失败

超出的 run 进等待区排队等许可，只有「线程 + 等待区都满」才当场失败并说明原因。 排队中的 run 不计入墙钟，因此「一直排不上」不会被超时兜住——兜底的是那三道上限， 以及中止回合时的级联取消。取消能穿过等待区：等许可的循环每 50ms 查一次取消标记， 被取消的 run 当场落「已取消」，不必等前面的 run 跑完。

归档配额与工具输出分开算（归档按 run 产生、含整份子会话 transcript），两者分居不同目录、各有各的上限， 清理互不掏空对方的窗口。

常见问题

  • 改了 maxDepth 没反应？先看改的是哪一半：深度判定每个顶层回合开始时重读，敲 /reload 后下一个回合就按新值；agent-run 池的线程上界在第一次提交 run 时定型，那一份要重启进程才变（它只影响能同时容纳多少条在跑的 run，见上表）。

  • 调大 maxSpawnsPerTurn 后编排还是拒绝？要一起把 treeTokenBudget 调大，否则封顶没变。
  • 不想要子代理了？把 enabled 设为 false，敲 /reload，task 工具就不再注册。

常见问题

我配了 agents.json，模型还是在用默认 agent？
默认 agent 是内置的 jellyfish，每次启动、每个新建会话都绑它，必须手动 /agent <agentId> 切换。用 /agent 先确认当前绑的是谁。
我只想拒绝两个工具，为什么 agent 什么都不能做了？
你大概写了 "allowedTools": []。显式空数组是「全拦」而不是「不限制」——想表达「其余不限制」就省略这个字段。
审批框一直不弹（或一直不超时）？
先看是哪种外壳：-tui 才弹框，-server 走 SSE，-cli 一律拒绝。再看 permission.approvalTimeoutSeconds：缺省 120 秒，写 0 表示永不超时。
提示词有长度上限吗？
没有上限——源码里既不校验长度也不截断：加载器把整份 md 读成字符串（只校验文件名是否安全，不看字节数），组装时把原文整段拼进 system prompt，而请求侧的机械裁剪只丢消息历史、从不裁 system prompt。代价是它整段占模型的上下文预算：每轮先按它的 token 从预算里扣一遍，写太长会把历史挤掉（被裁的是历史）。所以「没有硬上限」不等于「可以随便写」，够用为止。
改了 agents.json 要重启吗？
不用，敲 /reload 即可（它会重读配置、重建 agent 索引，并只重启配置段变了的插件）。但 subAgent 段里的 maxDepth / maxConcurrentRuns / maxQueuedRuns 是例外：需重启。
task 和 workflow 该用哪个？
只派一个子代理做一件事用内核自带的 task；「几件事可以同时做、再把结果合起来」用 workflow 插件的 spec。两者在内核里走同一条委派路径，并发、深度、预算、取消口径完全一致。

关键结论

  1. agent = 提示词（同目录的 {agentId}.md）+ 权限（三段工具名）+ 可选 model 偏好；agents.json 里不写提示词正文。
  2. 系统默认 agent 是内置的 jellyfish（default-agent.json，用户改不了），每次启动与新建会话都绑它，想用自定义 agent 必须手动 /agent 切换。
  3. 权限三段：字段缺失 = 不限制，显式 [] = 全拦；优先级 deniedTools > askTools > allowedTools。写「只拒绝两个工具」时千万别顺手写 allowedTools: []。
  4. askTools 在三种外壳下行为不同：-tui 弹框、-server 推进 SSE 由接口裁决、-cli 一律按拒绝处理（绝不静默放行）。
  5. allowedTools 不只收口主会话：它还决定子代理能看到哪些工具（只随委派生效）。工具名写错不会告警——权限名单在源码里只是一组字符串，没有任何一处拿它与实际注册的工具名对照。
  6. 子代理委派是内核自带的能力（task 工具 + delegatable: true），子代理与主会话相互隔离、不继承模型与历史，token 计入父会话，会话不留痕。
  7. subAgent 段里只有执行资源那一档需要重启：maxConcurrentRuns / maxQueuedRuns（以及 maxDepth 用于算池上界的那一份）在第一次提交 run 时定型；其余都是现读现用——maxDepth（深度判定）/ maxSpawnsPerTurn / runTokenBudget / treeTokenBudget 每个顶层回合开始时读，maxRounds 每次派 run 时读，runTimeoutMillis 每次起看门狗时读，archiveKeepFiles / archiveMaxBytes 每次归档时读，enabled 重算注册与组装提示贡献时读——这些 /reload 后即生效。
