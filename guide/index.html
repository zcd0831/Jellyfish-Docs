Jellyfish 详细使用指南

写给「想用 Jellyfish 干活」的开发者：每个功能点怎么用、每个配置项怎么写、插件怎么开发、 怎么接进已有的 Spring Boot 工程。不讲内核实现细节，只讲可操作的东西。

这套指南覆盖什么

  • 跑起来——环境要求、源码构建、第一个会话、三种运行模式怎么选；
  • 配得对——config.json / models.json / agents.json / jellyfish.json 四份配置文件的全字段表，含类型、必填、默认值、生效方式；
  • 用得顺——内置工具清单与参数、会话与压缩、@ 文件引用、权限与审批；
  • 扩得开——官方插件装哪些、怎么配；从零写一个自己的 Java / Python / Node 插件；
  • 接得进——把内核装进已有的 Spring Boot 应用，含多用户护栏与审批 / 提问接口的接法；
  • 排得了——现象 → 原因 → 解决 三段式的故障排查，覆盖模型、插件、审批、上下文、端口、整合冲突。

仓库角色你要不要它坐标 / 形态
Jellyfish 内核：三种外壳 + 装配 + 扩展点与插件运行时 + 插件 SPI。工具、命令、权限模式等能力都不在内核里 必然要。它产出唯一的可执行入口 jellyfish-cli-0.1.1.jar 父 POM 与 jellyfish-api / -infra / -core / -di 发中央仓库，坐标 io.github.zcd0831:jellyfish:0.1.1
Jellyfish-Plugins 官方插件集 + 插件开发教程。每个插件是独立打包的 PF4J jar 想读文件 / 跑命令 / 存会话就必须装，否则内核近乎空转 独立 Maven reactor，聚合坐标 io.github.zcd0831:jellyfish-plugins:0.1.1
Jellyfish-Spring-Boot-Starter 把内核搬进已有的 Spring Boot 容器，并补上内核没有的「用户」维度 只有当你要在自己的 Java 服务里用 agent 才需要 io.github.zcd0831:jellyfish-spring-boot-starter:0.1.1
Jellyfish/README.md:13-22（姊妹仓库表）、Jellyfish/AGENTS.md（模块依赖方向）、Jellyfish-Spring-Boot-Starter/pom.xml（内核依赖坐标）、Jellyfish-Plugins/README.md:8-28
三条容易误解的事
  • 插件不在内核仓库里：内核只保留插件机制与 SPI。拿到 jar 直接跑，你会发现除了系统命令什么都干不了——文件工具、shell、会话持久化全在插件仓库。
  • 插件与内核没有编译期依赖：插件对 jellyfish-api 是 provided，因此能独立构建、独立发版。注意 插件 POM 示例里的父 POM（jellyfish-plugins）未见发布到中央仓库（该仓库没有 release profile），站外开发时请按 12 插件开发 一节的说明直接用 jellyfish-api 坐标。
  • Starter 只是另一种装配方式，它不改内核、也不提供 HTTP 接口；它交付的是编程式 API，接口由你自己写。

怎么读这套文档

正文里的几种标记

  • 必填 / 选填 / 默认值—— 配置字段表的第 3、4 列，直接看标签即可，不必逐字读；
  • /reload 生效 / 需重启—— 改完这个字段要不要重启进程；
  • 【待确认】 / 【需核实】—— 在三个仓库的 README、示例配置、源码或官方文档里找不到出处的内容。本套文档宁可标出来，也不编造。
使用提示
  • 页内所有命令与配置块右上角都有复制按钮，可直接粘到终端。
  • 示例里的密钥一律写成占位符（sk-***、${OPENAI_API_KEY}），路径写成 /path/to/...—— 不要把真实密钥写进配置文件，正文里反复强调这一点是有原因的（见 05）。
  • 断网也能读：样式表内置了代码高亮配色；只有两张图依赖 CDN 上的 Mermaid，取不到时会退化成源码文本，不会变成空白。
  • 每页正文里给出结论时，都会附一条 文件:行号 或 文件:章节 形式的出处条，方便你去仓库里核对。

关键结论

  1. Jellyfish = 最小内核 + 能力全在插件 + 三外壳共用一份装配。不装插件它几乎做不了事，这是设计而不是缺陷。
  2. 配置文件只有四份（config.json 管「其它文件在哪」，另外三份管内容）， 内容类改完敲 /reload 即可，config.json 与插件 jar 的增删必须重启。
  3. 所有默认值的方向都是更严：项目级配置默认不加载、审批无人裁决即拒绝、插件无法自称只读。
  4. 想要「按用户隔离」，内核不提供——那是 Spring Boot Starter 的职责。
  5. 本套文档的每条命令与字段都标了出处；查不到的会写成 【待确认】，请在动手前自行核实。
