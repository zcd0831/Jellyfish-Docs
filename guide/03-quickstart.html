03 五分钟快速上手

这一页只做一件事：把「能跑起来 → 配一份模型 → 装插件 → 问一句话 → 看见工具真的被调用」这条最短路径走完。 每一步都是可直接粘贴的命令，每一步都说明它为什么必要。假设你已经按 02 安装与环境准备 拿到了可执行的 fat jar；如果还没有，先去那一页。

学习目标

  • 用 java -version / mvn -v 确认 JDK 与 Maven 满足要求；
  • 在不配模型的前提下跑通 -cli -p "/help"，确认 jar 起得来；
  • 写出第一份 .jellyfish/models.json，并用环境变量注入密钥；
  • 说清项目级配置默认不加载这条闸门，以及 --trust-project-config 与 TUI 确认框两条放行路径；
  • 装齐「最少必要」的三个插件，知道不装插件时它只能跑系统命令；
  • 让模型真的读一个文件，并在工具轨迹里亲眼看到那次调用。

第 0 步：环境自检（两条命令）

Jellyfish 的源码与目标版本都是 Java 1.8，构建要求 Maven 3.2.5 以上。 只运行不构建的话，Maven 可以没有，但 JRE 必须在 8 以上。 

java -version
mvn -v
项要求你现在该看到什么
JDK 8（源码与目标版本都是 1.8）；运行只需 JRE 8+ java -version 打出 1.8.0_xxx 或更高
Maven 3.2.5 以上（构建用；pom.xml 里打包插件的版本线以此为准） mvn -v 打出 Maven 版本与它用的 JDK
终端 -tui 需要可交互终端；-cli / -server 不需要 本页第 1～5 步全部只用 -cli，在任何终端或管道里都能跑
模型 一个 OpenAI 兼容的 API（没有也能跑命令，见第 1 步） 第 2 步才需要，随时可以去申请
先把命令敲短

fat jar 的路径很长，建议先设个别名，后面每一步都能少打一截： 

alias jellyfish='java -jar /绝对路径/jellyfish-cli/target/jellyfish-cli-0.1.2.jar'

本页为了说明「哪个文件是入口」，仍然把完整命令写全。

Jellyfish/README.md「环境要求」「安装与构建」两节（JDK 8 / Maven 3.2.5+ / 终端 / 模型四项要求、fat jar 路径与 alias 示例）

第 1 步：离线验证安装（不需要模型）

用 /help 确认 jar 真的起得来

是什么
一部分内核自带命令根本不需要模型配置（它们不发起 LLM 调用），因此可以拿它们把 「装没装好」和「模型配没配对」这两件事分开验证。这是排查问题的第一刀。
怎么用
java -jar jellyfish-cli/target/jellyfish-cli-0.1.2.jar -cli -p "/help"

看到命令清单就说明装好了：-cli 走单次调用、-p 给这一次的输入， 输入以 / 开头即走命令域。在碰别的旗标之前，先确保这一条能出结果—— 之后任何一次「跑不起来」，都可以退回到这一条来判断是安装问题还是配置问题。

配置

参数类型必填默认值含义示例
-cli 旗标 必填 不带任何参数时模式默认 -tui 单次调用模式：进一个输入、出一次结果后退出（只要带了参数，模式就必须显式给） -cli
-p, --print 字符串 选填 从 stdin 读到 EOF（管道可用） 单次模式的输入 -p "/help"

完整示例

# 方式一：把输入写在命令行上
java -jar jellyfish-cli/target/jellyfish-cli-0.1.2.jar -cli -p "/help"

# 方式二：从管道喂进去（不写 -p 时读到 EOF）
echo "/help" | java -jar jellyfish-cli/target/jellyfish-cli-0.1.2.jar -cli

常见问题

  • 报 Unable to access jarfile？路径不对。jar 不在当前目录就用绝对路径； 还没构建成功就先回到 02 安装与环境准备。
  • 退出码不是 0？2 是用法错误（参数缺失 / 冲突、没有输入）， 3 是启动失败（配置、插件或装配出错）。逐条含义见 04 三种运行模式。

能拿来「离线验安装」的命令不止 /help，下面这些都不需要模型配置：

命令离线能做什么
/help列出内核自带命令与插件带来的命令（插件装了才会出现）
/session（别名 /sessions）列出全部会话（需要会话持久化插件才看得到落盘的那些）
/status显示当前会话概要
/model查看（或切换）模型——用它就能确认模型配置到底读到没有
/compact preview只回报「将压缩多少条」，不发起压缩（压缩本身仍要压缩插件）
Jellyfish/README.md「快速开始 · 1. 先离线验证安装」、「常用命令」（离线可用命令清单）

第 2 步：配一份模型

写第一份 .jellyfish/models.json

是什么
要让模型说话，只需要告诉 Jellyfish 三件事：每个 provider 怎么访问（type / apiKey / baseUrl）、它有哪些模型、以及按需调参。 这些全写在一份 models.json 里；要按场景换一套工具权限与提示词，再配一份 agents.json（见 07 agents.json 与工具权限）。
怎么用
  1. 在工作目录（也就是你希望 Jellyfish 干活的那个目录）下建 .jellyfish/ 目录；
  2. 把下面这份 JSON 存成 .jellyfish/models.json；
  3. 把密钥放进环境变量，而不是文件里；
  4. 如果这是项目级配置（放在项目目录下），还要显式信任它——见下面的 danger 提示块。

完整示例（可直接用；openai 是 provider 的键名，不是必须叫这个名字）

{
  "defaultProvider": "openai",
  "defaultModel": "gpt-4o",
  "providers": {
    "openai": {
      "type": "openai",
      "apiKey": "${OPENAI_API_KEY}",
      "models": [{ "id": "gpt-4o", "name": "gpt-4o", "contextLength": 128000, "maxOutputTokens": 4096 }]
    }
  }
}

再把密钥放进环境变量（不要把密钥写进配置文件）：

export OPENAI_API_KEY=sk-***

字段说明（入门只用得到这些；sampling / vendorBody / vendorHeaders / cache 等全字段见 06 models.json 详解）

字段类型必填默认值含义示例
defaultProvider string 必填 — 不显式指定模型时用哪个 provider（键名必须在下面的 providers 里存在） "openai"
defaultModel string 必填 — 不显式指定模型时用哪个模型 "gpt-4o"
providers object 必填 — provider 字典；键名自取，它就是 /model 里 provider/model 的前半段 {"openai": { ... }}
providers.<name>.type string 必填 — 用哪套传输实现：openai / claude / deepseek / gemini / minimax 及其别名。写错会报错并列出内核认识的类型 "openai"
providers.<name>.apiKey string 必填 — 访问密钥。建议写 ${ENV_VAR} 由环境变量注入 "${OPENAI_API_KEY}"
providers.<name>.baseUrl string 选填 该 type 的官方地址 服务地址。必须填最终地址——出站请求不跟随重定向 "https://api.openai.com/v1"
providers.<name>.models array 必填 — 该 provider 下的模型清单 [{ "id": "gpt-4o", ... }]
models[].id string 必填 — 模型标识，/model 里 provider/model 的后半段，也是发给厂商的模型名 "gpt-4o"
models[].name string 选填 与 id 相同 展示名 "gpt-4o"
models[].contextLength int 选填 不写即 0，含义是「未知」 上下文窗口（token），内核用它算压缩预算。0 表示未知，内核就完全不按窗口裁剪历史（宁可让厂商自己报错，也不猜一个数把历史丢掉） 128000
models[].maxOutputTokens int 选填 不写即 0，含义是「未知」 单次最大输出 token，内核按次下发。0 表示未知，内核就不下发这个上限；唯一例外是 Claude 客户端（Messages API 必须给 max_tokens，未下发时它用自带缺省 4096 兜住） 4096

生效方式：/reload 生效——models.json 的内容改动敲一次 /reload 就会重读并重建模型索引，不用重启进程。

「必填」两字在仓库里没有明文

README 的说法是「要配的只有三件事：每个 provider 怎么访问（type / apiKey / baseUrl）、它有哪些模型、按需调参」，并没有逐个字段声明「必填」。 上表里标的 必填 是按这句话推断的（没有 type 就没有传输实现、没有 models 就没有可选模型）。默认值列写 — 表示「这个字段是必填的， 没有默认值可填」。

contextLength / maxOutputTokens 两格的默认值不是猜的：这两个字段在配置类里 都是原始类型 int，不写就是 0，而内核把 0 统一当 「不知道」处理——contextLength 为 0 就不按窗口裁剪历史 （输入预算取「无上限」），maxOutputTokens 为 0 就不往请求里放输出上限字段。 这条口径在插件侧的类型 ModelDescriptor 的类注释里写成了明文（「允许为 0，含义是不知道」， 并解释了为什么不让插件去猜一个看起来合理的值）。

常见问题

  • 写错一个键，为什么不报错？这份文件关掉了「未知字段」的报错： 表里没列出的字段就是不支持的，多写一个键既不会有提示、也不会有任何效果。
  • baseUrl 收到 301/302？出站请求不跟随重定向（跟随等于允许上游把你的 密钥头送到任意主机）。错误信息里会写明「重定向被禁止」以及目标主机与路径，把 baseUrl 改成最终地址即可。
  • maxOutputTokens 好像没生效？它由 maxTokensField 决定挂在 max_tokens 还是 max_completion_tokens 上——OpenAI 的推理模型（o 系）与 gpt-5 及之后只认后者，用错就是一次 Unsupported parameter 400。见 06 models.json 详解。

环境变量注入的写法

只有字符串值里的 ${VAR} 会被替换成环境变量，JSON 的 key 不替换。 三种写法： 

{
  "apiKey": "${OPENAI_API_KEY}",
  "baseUrl": "${MY_GATEWAY_URL:-https://api.openai.com/v1}"
}
写法含义
${VAR}替换为环境变量 VAR 的值。变量未设置时整份配置加载失败（不是留空、也不是跳过）——要容错就用下一行的写法
${VAR:-default}变量取不到时用 default
\${VAR}转义为字面量（不做替换）
不要把密钥写进配置文件

apiKey 这类敏感值通过环境变量注入，不要落到配置文件里——配置文件会被提交、会被分享、 会进备份。本页所有示例里的密钥都是 sk-*** 占位符。

注意 {agentId}.md 这类提示词文件是原文，不做模板插值，别指望在那里写 ${VAR} 能取到环境变量。

全局级 vs 项目级：放哪儿、什么时候生效

配置文件走「全局级 ~/.jellyfish/ + 项目级 <工作目录>/.jellyfish/」双源读取， 项目级优先。同名 provider / 模型以项目级整对象覆盖。

放哪儿作用范围适合什么代价
~/.jellyfish/models.json 这台机器上的所有项目 你日常用的那一套 provider 与模型，一次配好到处能用 换机器要重新拷
<工作目录>/.jellyfish/models.json 只在这个目录里启动时生效 某个项目要换模型 / 换网关 默认不加载，每次（或第一次）都要显式信任；文件内容一改，信任立即失效
坑：项目级配置默认不加载（这不是 bug）

<工作目录>/.jellyfish/*.json 默认不加载，只有被显式信任过才参与合并。 两处后果：

  • 你辛辛苦苦写的 .jellyfish/models.json「明明在那里」，/model 里却看不到它； 这种情况会额外发一条配置告警，但启动不会中断。
  • 没有终端可问时（-cli / -server）只会打印一行提示， 告诉你怎么才能加载，绝不擅自加载。

为什么要这样：项目级配置的读取基准是进程当前目录，内容取决于你在哪个目录里启动； 而它能决定的东西很重——models.json 里同名 provider 是整对象替换，baseUrl / apiKey 一改，该 provider 的密钥与全部对话正文就送到别处。这些文件会因为 git clone / git pull 凭空出现在工作目录里，所以闸门设在「这个目录可不可信」这一层。

两条放行路径（挑一条）

场景做法是否落盘
-cli / -server 启动时加 --trust-project-config 否，仅本次进程有效
-tui 启动时弹出确认框，选 y 加载并记住 是，记进 ~/.jellyfish/trusted-project-configs.json
-tui 同一确认框里选 o 仅本次加载 否 
# 路径一：CLI / Server，临时信任一次
java -jar jellyfish-cli/target/jellyfish-cli-0.1.2.jar -cli --trust-project-config -p "/model"

# 路径二：TUI，启动时在确认框里回答 y（记住）或 o（仅本次）
java -jar jellyfish-cli/target/jellyfish-cli-0.1.2.jar -tui
参数类型必填默认值含义示例
--trust-project-config 旗标 选填 不加载（缺省不信任） 信任并加载项目级配置（./.jellyfish/*.json），仅本次进程有效、不落盘 --trust-project-config
省事的做法：全局级放一份，什么都不用信任

「一路只读全局级时什么都不用做」——把同一份文件放到 ~/.jellyfish/models.json， 就不必每次启动都处理信任这回事。项目级只在「这个项目确实要不一样的模型」时才值得用。

另外，classpath: 形式的项目级路径（如 classpath:jellyfish/models.json） 不受这道闸管辖：它属于运行构件本身，与全局级同性质。Spring 接入方正是用它把配置放进自己的 resources，从而不必依赖工作目录（见 14 整合到 Spring Boot）。

Jellyfish/README.md「快速开始 · 2. 配一份模型」「配置 · models.json」「配置 · 项目级配置的信任」（双源合并、${VAR} 插值、信任单位是文件绝对路径 + 内容指纹、三种授予方式）；contextLength / maxOutputTokens 两格默认值：Jellyfish/jellyfish-infra/src/main/java/zcd/jellyfish/infra/config/Model.java:93-94,100-101（两字段是原始类型 int，JSON 里不写即为 0）、Jellyfish/jellyfish-api/src/main/java/zcd/jellyfish/api/extension/ModelDescriptor.java:11-16（「允许为 0，含义是不知道」的统一口径）、Jellyfish/jellyfish-core/src/main/java/zcd/jellyfish/core/prompt/PromptAssembler.java:342-344（>0 才下发输出上限）、Jellyfish/jellyfish-core/src/main/java/zcd/jellyfish/core/prompt/PromptAssembler.java:803-807 与 Jellyfish/jellyfish-core/src/main/java/zcd/jellyfish/core/compact/ConversationCompactor.java:851-855（<=0 视为无窗口，不裁剪）、Jellyfish/docs/constraints.md:614-615、Jellyfish/jellyfish-infra/src/main/java/zcd/jellyfish/infra/llm/ClaudeLlmClient.java:62,269-270（Claude 未下发时用 4096 兜底）

第 3 步：装插件（不装它只能跑系统命令）

插件不在内核仓库里

内核只保留插件机制与 SPI。拿到 fat jar 直接跑，除了系统命令之外几乎什么都干不了—— 文件工具、shell、会话持久化全在官方插件仓库 （Jellyfish-Plugins）。不装 jellyfish-plugin-tools， 模型连读一个文件都做不到，「快速上手」到此为止。

最少要装的三个插件

是什么
官方插件里这三个覆盖了「能干活」的最小集合：读写文件、跑命令、 把会话存下来。其余十个按需再加，见 11 安装与使用官方插件。
怎么用

先把插件仓库构建一遍，再把 jar 拷进扫描目录（缺省 ~/.jellyfish/plugins/）：

cd /path/to/Jellyfish-Plugins
mvn -q package -DskipTests

mkdir -p ~/.jellyfish/plugins
cp jellyfish-plugin-tools/target/jellyfish-plugin-tools-*.jar ~/.jellyfish/plugins/
cp jellyfish-plugin-shell/target/jellyfish-plugin-shell-*.jar ~/.jellyfish/plugins/
cp jellyfish-plugin-session-file/target/jellyfish-plugin-session-file-*.jar ~/.jellyfish/plugins/

插件仓库自带一个脚本可以一次拷完：./cpPlugins.sh（把各模块 target/*.jar 拷进扫描目录）。只想装几个就照上面的写法逐行拷。

拷完必须重启进程：新增 / 删除插件 jar 只在启动期确定（PF4J 在扫描目录下一层找 plugin.properties），/reload 管不了 jar 的增删。

仓库里只对 tools 给了字面拷贝示例。上面另外两行的 jar 名不是推断出来的：每个插件模块 只声明自己的 <artifactId>（与它 plugin.properties 里的 plugin.id 同名），版本继承父 pom.xml 的 0.1.2，全仓库没有一处 写 <finalName>，因此产物名就是 <artifactId>-<version>.jar—— 已构建的 target/ 里确实是 jellyfish-plugin-shell-0.1.2.jar 与 jellyfish-plugin-session-file-0.1.2.jar（同目录另有一个 shade 留下的 original-…jar，上面的通配不会命中它）。

装完能得到什么

模块 / plugin.id给什么不装的后果
jellyfish-plugin-tools 五个文件工具 read_file / write_file / edit_file / list_dir / grep_files；提问工具 ask_user； 输入框的 @ 文件引用；按路径收口的闸门 pathPolicy 模型无法读写文件、无法列目录、无法搜代码
jellyfish-plugin-shell shell 工具（/bin/sh -c 执行命令原文）+ 命令策略（分段判定、白名单准入、 可信表免审批、只读不打扰、灾难形状拒绝、命令替换与重定向升级审批、其余审批）+ !命令 输入指令。没有沙箱 模型跑不了命令，!命令 只是一段普通文本
jellyfish-plugin-session-file 会话持久化：一个会话一个 JSON 文件，并用 git 管理历史 /session、/resume、--session 都没有落盘的会话可用

配置

{
  "plugins": {
    "roots": ["~/.jellyfish/plugins/"]
  }
}

扫描目录写在 config.json 的 plugins.roots 里（顺序即扫描顺序，支持 ~ 与相对路径，相对路径相对进程工作目录解析，留空回退默认值 plugins）。 启用 / 禁用名单与逐插件配置段写在 jellyfish.json，变化由 /reload 生效； config.json 与插件 jar 的增删是 需重启。

验证

# 重启后，/help 里应该出现插件带来的命令
java -jar jellyfish-cli/target/jellyfish-cli-0.1.2.jar -cli -p "/help"

常见问题

  • 拷进去了但没生效？没重启进程。扫描目录与插件集合只在启动期确定。
  • 插件编译时找不到 jellyfish-api？插件仓库是独立 reactor， jellyfish-api 来自本地 Maven 仓库，改插件前先装内核： (cd ../Jellyfish && mvn -q install -DskipTests)。忘了这一步的表现是 「内核明明改了，插件这边编译却看不到」。

第 4 步：问第一句话

三种启动方式

是什么
三个外壳共享同一个入口与同一份装配，只靠启动参数区分。一个参数都不带直接运行 = -tui。
怎么用
# 交互界面（不带参数就等于 -tui，需要可交互终端）
java -jar jellyfish-cli/target/jellyfish-cli-0.1.2.jar

# 单次问答：进一句、出一次结果后退出（推荐第一次用这个）
java -jar jellyfish-cli/target/jellyfish-cli-0.1.2.jar -cli -p "总结一下这个项目"

# 显式指定交互界面
java -jar jellyfish-cli/target/jellyfish-cli-0.1.2.jar -tui
兜底只此一处：判据只有「参数个数为零」
  • 一个参数都不带（含 args 为 null）→ 模式定为 -tui， 等价于显式写 jellyfish -tui。
  • 只要带了任何参数，模式就必须显式给：jellyfish --verbose 一样报 「请指定启动模式」并退 2。这是刻意的——兜底不许扩成「内容推断」，否则「敲了没反应」 和「悄悄挂在等 stdin」两头都可能发生。

第一次提问时值得知道的三个参数

参数类型必填默认值含义示例
-p, --print 字符串 选填 从 stdin 读到 EOF 单次模式的输入；以 / 开头走命令域，否则走一次 LLM 对话 -p "总结一下这个项目"
--model 字符串 选填 用 models.json 的 defaultProvider / defaultModel 新建会话时指定模型，必须含 / --model openai/gpt-4o
--session 字符串 选填 新建会话 切换到已有会话（需安装 jellyfish-plugin-session-file 等持久化插件；会话不存在时按用法错误退 2） --session a1b2c3d4

完整示例：把回答与诊断分开存，回答进 answer.txt、诊断进 diag.txt

java -jar jellyfish-cli/target/jellyfish-cli-0.1.2.jar -cli -p "总结这个项目" > answer.txt 2> diag.txt

常见问题

  • 敲了没反应、像卡住了？检查后面跟了什么参数。带了参数却没给模式会被拒绝退 2； 给了 -cli 但没给 -p 会从 stdin 读——在终端里它就等着你输入，用 Ctrl-D 结束。
  • 回答里有控制字符被吃掉？这是刻意的：写出前一律过 ControlChars， 重定向到文件时回答里的控制字符也会被剔掉。

第 5 步：确认工具调用真的发生了

让模型读一个文件，然后在工具轨迹里看它

是什么
「模型回答了」和「模型真的用了工具」是两件事。工具轨迹是内核按会话里 assistant 的 toolCalls 渲染出来的，看到它就说明这一整条链路（权限判定 → 插件执行 → 结果回灌）真的跑过了。
怎么用
# 让它读一个真实存在的文件（换上你自己目录里的文件名）
java -jar jellyfish-cli/target/jellyfish-cli-0.1.2.jar -cli -p "读一下 README.md 的前 40 行，用三句话总结"

# 想把调用参数也打出来，加 --show-tool-args
java -jar jellyfish-cli/target/jellyfish-cli-0.1.2.jar -cli --show-tool-args -p "读一下 README.md 的前 40 行，用三句话总结"

单次模式的工具轨迹默认只给「开始」与「结束」两行（形状示意，参数以你实际那次调用为准）：

→ read_file
← read_file 完成（1234 字符）

加 --show-tool-args 会在其后补上单行、最多 200 字的调用参数：

→ read_file {"path": "README.md", "limit": 40}

配置

参数类型必填默认值含义示例
--show-tool-args 旗标 选填 不显示（工具轨迹只有开始 / 结束两行） -cli 的工具轨迹行上打出调用参数（单行，过长截断；TUI 用 Ctrl+E / /toolargs）。只归 -cli，-tui / -server 带上它退 2 --show-tool-args
--show-thinking 旗标 选填 不显示（思考过程默认折叠） 在工具轨迹之外单独打出思考过程。只归 -cli（TUI 用 Ctrl+T / /thinking） --show-thinking
参数不脱敏，这是明说的

--show-tool-args 打出来的调用参数不做脱敏：外壳按参数名猜不出哪个是密钥， 遮不住命令原文与写入正文这些真正会出事的地方。要看参数就别把带密钥的命令往日志或截图里贴。 TUI 的 Ctrl+E 同此口径。

常见问题

  • 一行工具轨迹都没有？按这三条排：① 三个插件装了吗、重启了吗（没装 jellyfish-plugin-tools 就没有 read_file）；② 工具是不是被 agent 策略写进了 askTools——-cli 没有审批界面，askTools 里的工具一律按拒绝处理， 绝不静默放行；③ 模型本身是否可用（没配模型时一发对话就会提示没有可用模型）。
  • 模型说它看不到文件？相对路径按进程工作目录解析，确认你启动命令时在哪个目录里。
  • 轨迹里参数被截断了？形如「… 参数过长，已省略后续内容」，这是按显示行数收尾的设计； CLI 侧是单行 200 字封顶。

常见问题

没配模型会怎样？

是什么
命令照常能用——/help /session /status /model /compact preview 都不需要模型；一发对话就会提示没有可用模型。
怎么用
按本页第 2 步建一份 models.json（~/.jellyfish/ 或项目级 + 信任）。

裸跑 jellyfish（不带任何参数）会干什么？

是什么
等价于 -tui，因此同样需要可交互终端，在管道 / CI 里一样退 3 （这是有意的：否则终端界面会永久挂住）。
怎么用
想跑单次问答请显式写 -cli -p "..."：兜底只认「一个参数都不带」，带了参数却没给模式 （如 jellyfish --verbose）仍判用法错误退 2。

-cli 下工具调用总被拒绝？

是什么
-cli 没有审批界面，askTools 里的工具一律按拒绝处理（绝不静默放行）。
怎么用
要在无人值守下跑，就别把该工具放进 askTools；要人工确认就用 -tui 或 -server。shell 这类插件另有白名单与可信表的口径，见 11 安装与使用官方插件 与 10 权限与审批。

-cli 下 ask_user 会怎样？

是什么
不会失败、也不会挂住：-cli 不挂答复者，工具立刻返回一条「当前外壳没有交互界面， 无法把提问送达用户」，模型据此照自己的判断继续。
怎么用
真要人回答就用 -tui（浮层选择）或 -server（走 HTTP 作答）。

改了配置不生效？

是什么
分的很清楚：models.json / agents.json / jellyfish.json 三个内容文件 /reload 生效；config.json、新增 / 删除插件 jar 需重启。
怎么用
java -jar jellyfish-cli/target/jellyfish-cli-0.1.2.jar -cli -p "/reload"
java -jar jellyfish-cli/target/jellyfish-cli-0.1.2.jar -cli -p "/model"   # 看模型索引有没有更新

如果改的是项目级文件，先确认这一项：项目级文件存在但未被信任时不加载， 会额外发一条配置告警。

Jellyfish/README.md「常见问题」（没配模型、裸跑 jellyfish、-cli 下工具总被拒绝、-cli 下的 ask_user、改了配置不生效五条）

关键结论

  1. -cli -p "/help" 是不需要模型的验安装手段；把「装没装好」与「模型配对没有」分开验证。
  2. 配模型只要三件事：provider 的 type / apiKey / baseUrl、它有哪些模型、按需调参；密钥用 ${ENV_VAR} 注入，不写进文件。
  3. 项目级配置默认不加载（信任单位是「文件绝对路径 + 内容指纹」，内容一改就失效）。CLI / Server 用 --trust-project-config 信任一次，TUI 启动时在确认框回答 y 或 o。
  4. 不装插件时内核近乎空转：最少装 tools / shell / session-file，拷进 ~/.jellyfish/plugins/ 后必须重启。
  5. 兜底只认「一个参数都不带 = -tui」；带了任何参数就必须显式给模式，否则退 2。
  6. 看到工具轨迹（→ 工具名 / ← 工具名 完成（N 字符））才算真的用上了工具；--show-tool-args 能加打参数，但参数不脱敏。
  7. 三个内容文件改完 /reload 生效，config.json 与插件 jar 的增删需重启。
